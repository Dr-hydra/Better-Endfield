# BEM 创作者指南（第一版草案）

状态：正式 BEM 1.0 尚未实现。本文先约定创作流程和兼容边界，不能作为现有二进制格式规范。
现用转换命令见 [转换工具 README](../tools/CustomModel/README.md)，
已支持能力见 [当前兼容性声明](CUSTOM_MODEL_CAPABILITY_COMPATIBILITY_20260918.md)。

## BEM 的用途

BEM 是交给 Better Endfield 运行时装配的模型数据包。作者在电脑端准备和转换资源，
玩家导入 BEM；手机端无需解析 EFMI 配置或执行 Mod 脚本。
当前只有 PC 自定义模型运行时完成了这些样本验证，Android 仍需移植与独立验证。

第一版计划支持静态外观：替换/保留/隐藏指定组件、沿用游戏动画骨架、
将多个来源骨骼重映射到局部 palette、按绘制段使用不同原生材质，以及替换明确绑定的纹理。
不承诺任意 Shader 特效、源 Mod 按键面板、自动生成低模、自动分片或新增动画系统。

## 作者需要准备什么

1. 目标角色、游戏资源版本和目标平台，以及对应的已核实 profile。
2. 模型几何、UV、蒙皮权重和明确骨骼来源。合并骨架时必须保持 bindpose 和 Mesh 空间一致。
3. 每个绘制段所用的原生材质来源，以及纹理对应的具体属性/原纹理。
4. 要导出的固定外观列表。源包有多套衣服时，分别命名并指定稳定 ID 和默认外观。
5. 包名、作者、版本和资源来源/授权说明，随发布说明交付。

第一版没有现成的通用 Blender/FBX 直出插件。现有路径仍通过已支持的转换器和 profile
生成 v24/v25；新工具完成前不发布虚构的 BEM 1.0 导出命令。

## 已确认的多外观与压缩设计

一个角色包可包含多套固定外观，第一版由管理 UI 选择，下次启动游戏生效。
每套外观独立描述完整部件配置，引用共享几何/骨骼/材质/纹理；不要求重复打包相同资源。
打包器按资源去重并独立使用 Zstd 压缩（默认等级 9，不划算时保留 raw），
加载器只读取所选外观需要的数据。压缩无损，不降低贴图分辨率或模型精度。
游戏内热切换尚未实现，包体积也不等于运行时内存占用。

角色 profile 的分发尚在讨论：建议由项目提供已核实的角色资料，创作工具按需获取，
导出时把包实际需要的适配子集写进 BEM。作者不用逐包重新采样，也不需要随包发布原始 dump。

## 制作约束

- 顶点属性必须符合目标声明。不能仅凭 stride 一样就判断兼容。
- 几何支持 UInt16 和已放行的 UInt32；超过 16 位寻址范围时不能强行截断。
- 16 位源骨骼索引可以参与离线重映射，但当前输出为 UINT8 局部 palette 索引，
  每组件最多 256 个 palette 项。骨骼总数和每顶点影响数是两种不同限制。
- 材质沿用游戏原生 Shader。离线转换器不会把任意 HLSL 自动翻译成游戏材质。
- 同一纹理在多个材质上的绑定必须分别明确；正式格式建议共享数据，避免重复存储。
- 高模不天然禁止在 Android 使用；但 PC 测试通过不能证明移动端可用。
  需同时满足目标资源、骨骼/材质契约和设备能力，再检查动画、内存与帧耗时。
- LOD0 替换不会自动得到相应低模。现有运行时启用 Mod 时会锁定 LOD，作者应据此评估多角色场景。

## 验证与发布

将“结构通过”“目标资源匹配”“实机通过”分开记录。发布说明列出包版本、目标 profile、
验证过的游戏版本/平台、固定外观状态、材质近似或缺失效果、实测范围。
PC、Android、世界与角色详情的未测项目明确标记，不因为同角色同名自动填为通过。

实机只针对修改内容：几何/骨架改动检查动作、接缝与变形；材质改动检查相应部位；
资源交付/LOD 改动再检查重入界面、AI 切换等。无需每次重复所有已通过的角色测试。

遇到拒绝导入，先查看具体原因：目标不符、声明不符、索引越界、palette 超限、
材质来源缺失或设备能力不足。不要删除校验字段、冒用 profile 或改版本号来强行加载。

正式版发布前还需要补齐：安装/导出命令、最小示例包、完整字段参考及带实际示例的错误说明。
协议讨论见 [BEM_V1_DESIGN_DRAFT.md](BEM_V1_DESIGN_DRAFT.md)。
