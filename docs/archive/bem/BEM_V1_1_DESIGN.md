# BEM v1.1 组合选择与热切换兼容设计（历史草案）

日期：2026-09-23。本文件保留设计讨论；落地字段、限制与实际行为以 [BEM_V1_1_SPEC.md](BEM_V1_1_SPEC.md) 为准。尤其是索引已改为每条候选 draw 独立引用 payload，以保证未选 draw 专用字节不进入加载路径。BEM 1.0 见 [BEM_V1_SPEC.md](BEM_V1_SPEC.md)。

## 用户行为

一个源 Mod 仍是一个 `.bem` 和一个包卡片。互斥服装是一个选项组；发型、局部部件、材质等可独立变化的内容各是自己的组。管理器保存组选择，游戏下次启动应用。v1.1 **不提供游戏内热切换 UI、按键或替换事务**，但同一个已安装包必须能在未来实现这些功能时直接从组合 A 切到 B，再切回 A，无需重新转换或导入。

Shader、RabbitFX、逐帧脚本、连续滑块和源 INI 命令执行不在 v1.1 静态组合支持范围。转换器必须将这些效果标为不支持或失败，不得默默省略后宣称完全等价。

## 文件与清单

保留 40 字节头、payload 目录、压缩编码、原生 target 身份和现有 mesh/texture payload 表。新包头为 `major=1, minor=1`，必需能力含 `composable-options`；升级后的读取器继续接受 `minor=0`。旧读取器按现有逻辑拒绝 `minor=1`，不会把新清单错当固定外观。

v1.1 不再枚举每个完整组合的 `appearances[]`。拟新增以下纯数据字段，具体键名在实现写入器前锁定：

```json
{
  "option_groups": [
    {"id":"outfit","name":"服装","default":"a",
     "choices":[{"id":"a","name":"外观 A"},{"id":"b","name":"外观 B"}]},
    {"id":"part21","name":"局部部件","default":"on",
     "available_when":{"eq":["outfit","b"]},
     "choices":[{"id":"on","name":"显示"},{"id":"off","name":"隐藏"}]}
  ],
  "component_rules": [
    {"target":0,"candidates":[
      {"when":{"eq":["outfit","a"]},"operation":"keep"},
      {"when":{"eq":["outfit","b"]},"operation":"replace","mesh":0}
    ]}
  ]
}
```

`id` 是稳定的配置键，显示名不是；升级包时保留相同语义的 ID。`available_when` 只能引用清单中较早的组，因此可按顺序求值而没有循环。不可用组在设置中保留旧 choice，以便 A→B→A 后恢复；求资源规则时，它的有效值为“不可用”，该组上的任意 `eq` 均为 false。保存值缺失或已删除时使用默认 choice。联动键或不能任意组合的源状态需要显式约束；默认配置和用户选择都必须可达。

条件仅允许布尔常量及有限树 `eq`、`all`、`any`、`not`，禁止脚本、路径和任意表达式。每个 target 在任何可达设置下必须恰有一条操作候选成立：`keep`、`hide`、`replace`。每个替换 mesh 的候选 draw 可以带 `when`，并引用源 IB 的 `start/count`、材质槽和纹理 ID；选中后按清单顺序将这些源索引段复制为连续输出 IB，重新计算 draw start。允许明确声明的重叠源区间供两个材质 draw 重用。选中后的 draw 至少一条，且 index count 等于所选 draw count 之和；未选 draw 引用的纹理不进入输出模型。

最终规范采用容器 2 GiB、manifest 4 MiB、payload 目录 4096、单 payload 512 MiB、BEM 1.1 单次选定状态的已解码 payload 缓存合计与重建后常驻资源分别 768 MiB、32 张纹理、256 条最终 draw、64 个选项组及每组 16 项。1.0 的“最多 64 个完整外观”不套用到 1.1 的组合数。创作者工具用精确多值决策图验证全部可达状态，超过明确的图复杂度上限时拒绝；加载器对当前选择再次验证。

## 保存配置与选择计划

Windows `runtime.ini` 的 v1.0 `appearance=<id>` 保持原义。v1.1 拟使用 `options=outfit:a&part21:on`：组和值 ID 只允许既有稳定 ID 字符集，不含 `:`、`&`、`,`、`;`，使配置在 INI 与 Android 当前逗号分包的启动参数中无歧义。缺省组使用包内默认值；编码按清单组顺序规范化。Android 安装索引持久化同样的组 ID→choice ID 映射，游戏侧启动参数按包顺序传入选项串。现有 Windows/Android 运行配置读取缓冲区和解析器均设为 64 KiB；在约 551 个包的量级下必须统一提高上限（建议 1 MiB）并做边界测试，不能靠压缩成完整组合 ID 绕过。

加载器先读头、manifest 和 payload 目录并检查引用，再以 `SelectedPlan(manifest, saved_options)` 纯函数求出有效组值、每个 target 的唯一操作、按序的 draw、纹理与 payload ID。构造计划不读任何 payload；解码器只读取、解压和上传计划引用的 payload，共享 payload 本次只读一次。未选组合专用 payload 的读取次数、解压次数和 GPU 创建次数必须为零。安卓安装器把整包复制到游戏私有**磁盘**目录供后续选择使用，不等于游戏模型加载时把整包读进内存。

未来的热切换流程可持有同一包的 manifest/目录：对新组值生成新计划，在后台准备新选择，复用两边共有资源，成功后原子替换并释放旧选择专有资源，失败时保持旧模型。当前实现只需保证包内资源完整、选择计划可重算且资源 ID/组 ID 稳定；切换瞬间的双态内存峰值及替换事务是后续运行时工作，不能从 768 MiB 的单态预算推断。

## 验收

用同一 `.bem` 在无 UI 的内部测试中依次生成 A→B→A 的计划和模型；两次 A 的组件、索引、draw、材质与纹理引用一致，整个过程不重新导入、不改写包。为文件读取器加 payload ID 计数，检查每次只访问当前计划引用的 payload。覆盖重叠 draw、共享 payload、无效组合、隐藏组恢复、损坏引用与旧 1.0 包回归。首批源样本为 M0170、M0332 和别礼的嵌套 draw/贴图组合；无需把全部 551 包逐一实机测试当成验收条件。

需要同步修改 Python 写入/验证器、原生读取器与配置解析、Windows/Android 包管理服务及界面。v1.1 UI 在一个包卡片中先显示主服装，再显示当前适用的局部组；隐藏组保留先前选择，重新显示时恢复。保存按钮仍提示“下次启动游戏生效”，不出现热切换入口。当前 Android 包管理页先统一为主应用的深色卡片样式，v1.1 组控件要在解析器和索引格式落地后接入，不能把 1.0 的单外观下拉框当成已支持组合。
