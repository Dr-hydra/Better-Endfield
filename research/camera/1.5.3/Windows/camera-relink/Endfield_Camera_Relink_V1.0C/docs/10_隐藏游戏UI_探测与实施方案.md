# 10 隐藏游戏 UI —— 探测结论与实现（**已实现**）

> 版本: 模块 **1.0.0ak** / 插件 **0.3.8**（探测过程用的指令 63/64/65 从 1.0.0ai 起可用）。
> 本文记录：探测怎么做的、结论是什么、最终怎么实现、出问题怎么看。
> 可行性评估见 `09_隐藏游戏UI_可行性评估.md`；现场排查见 `03_故障排查.md` §10。

## 0. 结论速览（2026-09-14 实测）

| 问题 | 结论 |
| --- | --- |
| 能在不进原生相机的前提下隐藏 HUD 吗 | **能** —— 面板复选框「隐藏游戏 UI（拍摄用）」 |
| 会像原生 X 那样让键位失效吗 | **不会** —— 实测隐藏期间移动/跑动/普通攻击/技能全部照常 |
| 动的是什么 | 只把**只渲染层 5 的 UICamera** 的渲染遮罩压成 0 |
| 世界画面受影响吗 | 不受 —— 世界由 `MainCamera` 渲染，它的遮罩**不含层 5**，两者零重叠 |
| 可逆吗 | 可逆 —— 走游戏自己的接口，撤销后遮罩自己回到 `0x20` |
| 意外情况 | 游戏重建配置栈（如按 ESC 呼出菜单）时默认**放行**显示界面，关掉后自动重新隐藏 |


---

## 1. 为什么不能走"原生相机的 X 键"

原生相机模式里按 X 确实能隐藏 UI，但实测有两个硬伤：

| 硬伤 | 后果 |
| --- | --- |
| 很多键位失效 | 拍摄时无法用键位切换动作/镜头，正好卡住"边打边拍" |
| 原生相机里不能攻击 | 战斗镜头拍不了 |

所以 X 那条路被归为**最后手段**。要在"正常游戏状态"里隐藏 UI，我们把约束写成四条：

- **C1** 不进入原生相机模式
- **C2** 不改变任何键位语义（不合成按键、不改 InputManager 状态）
- **C3** 角色攻击/移动等输入必须照常可用
- **C4** 不碰账号 UID 水印（不做任何截图/渲染到纹理的二次处理）

同时**排除**所有会改 UI *逻辑状态*的做法 —— `SetActive(false)`、`canvas.enabled=false`、
`CanvasGroup.blocksRaycasts=false`、`CanvasGroup.alpha=0`。它们会让游戏的 UI 逻辑（按钮、
提示、状态机）与显示不一致，可能在战斗中引发异常。**只允许改渲染层**（相机与图层）。

---

## 2. 渲染层只有两条路

| 方案 | 做法 | 前提 | 输入影响 |
| --- | --- | --- | --- |
| **A（首选）** | 改 **UI 相机的 cullingMask**（或走游戏自己的遮罩配置栈） | 游戏的 HUD 由一台独立 UI 相机渲染 | 无（纯渲染） |
| **B（备选）** | 把 HUD 根节点的 **layer** 挪到一个没有相机渲染的层 | HUD 是 `ScreenSpaceCamera`/`WorldSpace`（Overlay 不吃相机遮罩） | 无 |

---

## 2.5 体检结论（2026-09-14 实测，**方案 A 定案**）

指令 64 一次就照清了整条链路 —— 世界与 HUD 由**两台遮罩零重叠的相机**渲染：

| 对象 | 遮罩 | 说明 |
| --- | --- | --- |
| `CameraManager.get_mainCamera()` | `0xAFFFDBDF` | 名 `MainCamera`，depth 0，**位 5 = 0（不渲染 UI 层）** |
| `CameraManager.get_uiCamera()` | `0x00000020` | 名 `UICamera`，depth 2，**只渲染层 5** |
| `CameraManager.get_lodStreamingCamera()` | `0xAFFFDBDF` | 就是同一台 MainCamera |
| `GetUICamDefaultCullingMask()` | `32` | 游戏自己的"UI 相机默认遮罩" |
| `GetMainCamDefaultCullingMask()` / `GetMainCameraCullingMask()` | `0xAFFFDBDF` | 主相机侧 |

⇒ **动 UICamera 的遮罩，既碰不到世界画面，也不涉及任何输入/角色状态**（C1~C4 全满足）。

游戏的写入/开关接口（同一份体检的签名清单给出）：

| 接口 | 用途 |
| --- | --- |
| `_SetUICameraCullingMask(int)` | 直接写 UI 相机遮罩 |
| `AddUICamCullingMaskConfig(string,int)` / `RemoveUICamCullingMaskConfig(string)` | **命名配置栈**（增删一条） |
| `_UpdateUICamCullingMask()` | 配置栈 → 实际遮罩的"应用"函数 |
| `_CurrCameraNeedHideHUD()` | 游戏自认为"当前该不该藏 HUD"（原生 X 那套的判断，只读） |
| 字段 `uiCameraCullingMaskConfigs` / `m_needHideHUD` / `m_targetEnable` | 配置栈与状态 |

**原生相机的 X 隐藏 UI 就是这么做的**：往 `uiCameraCullingMaskConfigs` 加一条命名配置，再
`_UpdateUICamCullingMask()`。我们照做，但**不调用 `_UpdateHUD()`**（它绑定在原生相机的输入/状态机上，
会带来 C1/C2 问题）。

> 附带发现：本 build **没有导出** `il2cpp_array_length` / `il2cpp_array_addr_with_size`
> （体检打印"数组API=0"），所以 `Camera.allCameras` 枚举不可用 —— 不影响结论，目标相机直接
> 用 `get_uiCamera()` 拿（1.0.0aj 已把它改成首选路径）。

**剩下的唯一未知**：往哪个通道写才"粘得住"（游戏会不会自己把遮罩改回去）。这就是指令 65 的任务。

## 3. 探测轮：三条指令

全部由运行时指令触发，**不被调用时没有任何副作用**；默认行为与 1.0.0ah 完全一致。

最省事的方式是用包内的一键探测脚本（发指令 + 只回显"本次新增日志"里的 `[ui]` 行）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\ui_probe.ps1 -Step audit   # 只读体检
powershell -ExecutionPolicy Bypass -File tools\ui_probe.ps1 -Step hide    # 隐藏 3 秒后自动还原
```

`-Step` 取值：`audit`(指令 64) / `inv`(指令 63) / `hide`(指令 65 隐藏) / `restore`(指令 65 立即还原) /
`main`(指令 65 对 Camera.main 下手，整屏黑，仅机制对照)；`-Hold 秒数` 改自动还原时间。

也可以直接发指令（探测指令请用 `-Repeat 1`，避免重复执行）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\send_cmd2.ps1 -Id 64 -Repeat 1
```

| 指令 | 参数 | 作用 | 是否改状态 |
| --- | --- | --- | --- |
| **63** | 无 | 导出 **UI 符号清单**（只读元数据）→ `game_mod\EndfieldCamLink_ui_inventory.log` | 只读 |
| **64** | 无 | **UI 体检**：① 相机清单 ② UI/图层成员完整签名 ③ "0 参 → Camera" getter 候选 ④ "0 参 → int" 的层/遮罩 getter | 只读 |
| **65** | `-A0 1 -A1 0 -A2 3` | **写入-测量**：把 UICamera 遮罩写成 0（不渲染），3 秒后自动还原 | 写渲染层，自动还原 |

附加开关：`-Id 65 -A0 0` 手动立即还原（兜底）；`-Id 65 -A1 1` 对 `Camera.main` 下手（**整屏黑**，只做机制对照）；
`-Id 65 -A1 2` 选非 main 的相机。

指令 65 的两条写入通道（自动依次试，日志会说明哪条生效）：

| 通道 | 做法 | 为什么 |
| --- | --- | --- |
| **1（首选）** | `AddUICamCullingMaskConfig("ECLHideUI", 0)` + `_UpdateUICamCullingMask()` | 游戏自己的机制，最不容易被覆写；还原 = `RemoveUICamCullingMaskConfig("ECLHideUI")` |
| **2（兜底）** | `_SetUICameraCullingMask(0)`（没有则 `Camera.set_cullingMask`） | 通道 1 没生效（例如配置栈语义不是取交集）时用 |

读回有三次：写入前 → 写入后立刻 → **保持中（约一半时长）**。第三次是关键：若它显示遮罩已被改回，
说明该通道不粘，实现时必须改用另一条通道或每帧重写。

### 3.1 指令 64 体检结果怎么读

日志在 `game_mod\EndfieldCamLink.log`，行首都是 `[ui]`。四块关键输出（下面是本次实测的真实片段）：

```
[ui] ① UnityEngine.Camera.allCameras: 枚举结果=N 台
[ui]    相机[0] 名='...' 遮罩=0x........ 启用=1 深度=0.0 clearFlags=.. 渲染到纹理=0 类=... 位=[0,5,8,...]
[ui]    相机[1] ...  <== 这就是 Camera.main
[ui] ② CameraManager / CameraUtils 里 UI·图层·遮罩 相关成员的完整签名:
[ui]        M get_uiCamera() -> UnityEngine.Camera
[ui]        M _SetUICameraCullingMask(...) -> System.Void
[ui] ③ CameraManager/CameraUtils 中 '0 参 -> UnityEngine.Camera' 的 getter 候选:
[ui]    getter get_uiCamera() -> UnityEngine.Camera (CameraManager 实例)
[ui]      -> 名='UICamera' 遮罩=0x........ 启用=1 ... 位=[...]
[ui] ④ CameraManager/CameraUtils 中 '0 参 -> int' 且名字像 层/遮罩 的 getter 候选:
[ui]    int-getter GetUIModelLayerMask() -> 5 (0x00000005)
```

`位=[...]` 是"这台相机渲染哪些层"的位列表。本次实测给出的判定全部落在第一行与第三行：

| 观察 | 本次实测 | 结论 |
| --- | --- | --- |
| 有第二台相机，名称/类名像 UI | `UICamera`（`get_uiCamera()`） | **方案 A 成立** |
| 出现了 `_SetUICameraCullingMask` / `AddUICamCullingMaskConfig` 等接口 | 全部存在 | 优先走**游戏自己的配置栈**（通道 1） |
| 枚举结果 = 0 且提示"数组 API 缺失" | 本 build 确实没导出数组 API | 不影响：目标直接用 `get_uiCamera()` |

### 3.2 指令 65 写入-测量怎么读

它是**决定性实验**：写 0 → 读回 → 保持中再读回 → 3 秒后自动还原。看这几条日志：

```
[ui] 写入前: 名='UICamera' 遮罩=0x00000020(32) ... 位=[5]
[ui] 游戏自认为'该不该隐藏 HUD'(_CurrCameraNeedHideHUD)=0 (游戏此刻不想藏)
[ui] GetUICamDefaultCullingMask()=0x00000020(位=5)
[ui] 通道可用性: 游戏配置栈=有(Add/RemoveUICamCullingMaskConfig + _Update) | _SetUICameraCullingMask=有
[ui] 通道1(游戏配置栈): 加条目 ECLHideUI=0 并让游戏自己应用
[ui]   配置栈通道读回: 0x00000000 OK(配置栈通道有效)
[ui] 保持中读回: 遮罩=0x00000000 仍然隐藏 -> 写入粘住了 (通道=游戏配置栈)
[ui] 还原(到期自动还原): 还原前=0x00000000 写回=0x00000020 还原后=0x00000020 OK
```

| 观察 | 结论 |
| --- | --- |
| 配置栈通道读回 = 0，**且画面 UI 消失**，键位/攻击照常 | 用通道 1 实现（最稳） |
| 配置栈没生效（"不等于 0"），直接写读回 = 0 | 用通道 2 实现 |
| 保持中读回 ≠ 0 | 该通道不粘 → 换通道，或实现时每帧重写 |
| 读回 = 0 但**画面 UI 没变** | 这台相机不管 HUD → 退回方案 B |
| 拒绝执行（"找不到 UI 相机…不做任何写入"） | 没有独立 UI 相机 → 方案 B |

**安全设计**（本探测不依赖任何人工兜底）：
- 写入前先读回原值，只写渲染层，不动 UI 逻辑状态；
- 到期**由每帧 tick 自动还原**（`GameSysUiTick` 挂在 `OnGameTick` 最前面，与是否武装无关）；
- 还原时**重新取一次相机**再写回（不跨帧缓存托管指针，避免 GC 后悬空）；
- 还原双保险：先用过的通道先撤销（`RemoveUICamCullingMaskConfig`），若结果仍不等于原值，再直接写一次；
- 还原失败每帧重试，超过 10 秒才放弃并写日志提示"切一次场景让游戏重配遮罩"；
- 找不到 UI 相机 → **拒绝写入**；
- 解释 `allCameras` 数组前三重校验（声明类型含 `Camera[`、长度 == `allCamerasCount`、长度 ≤ 32），任一不满足就不读元素。

## 4. 实现方案（体检已定案）

### 4.1 机制

**只动 `UICamera` 的遮罩**（层 5），并且优先用游戏自己的配置栈：

```
隐藏: AddUICamCullingMaskConfig("ECLHideUI", 0) → _UpdateUICamCullingMask()
还原: RemoveUICamCullingMaskConfig("ECLHideUI") → _UpdateUICamCullingMask()
兜底: _SetUICameraCullingMask(原值)
```

不调用 `_UpdateHUD()`（它读原生相机的状态，会把我们拖回 C1/C2 的坑）；不碰 `m_needHideHUD`
（那是游戏自己的状态，改它就是改 UI 逻辑状态）。

### 4.2 面板（已实现，插件 0.3.8）

- 「镜头模式」下面新增复选框 **隐藏游戏 UI（拍摄用）**（属性 `ef_bridge_hide_ui`，默认不勾）；
- 勾选 = 包里 `FLAG_HIDE_UI`（**bit 6**）置位，模块边沿触发一次隐藏；取消 = 清位，模块恢复显示；
- 勾选状态下模块会持续保持（帧末重申），并显示"隐藏中/放行中"状态日志。

### 4.3 协议（已实现）

- 复用共享内存里的空闲标志位 **bit 6**（`kFlagHideUi`；bit 5 已被"随角色"占用），**不改包长、不改版本号**；
- 老插件不置该位 → 行为与从前完全一致。

### 4.4 写入通道与"最后一句话"

```
隐藏: AddUICamCullingMaskConfig("ECLHideUI", 0) → _UpdateUICamCullingMask()
      (没生效才退回 _SetUICameraCullingMask(0) / Camera.set_cullingMask(0))
保持: 每帧在 CinemachineBrain 之后的钩子里(渲染前最后一个时机) GameSysUiEnforce()
显示: RemoveUICamCullingMaskConfig("ECLHideUI") → _UpdateUICamCullingMask()
      (若结果仍是 0, 再直接写回勾选时记录的"常规遮罩" —— 双保险)
```

为什么必须"帧末重申"：游戏的 UI 状态一变就会**重建整个 `uiCameraCullingMaskConfigs`**（实测按
ESC 呼出界面时遮罩从 `0` 变 `0x420`），所以只写一次是不够的。

策略（用户选定 **尊重游戏**）：

| 读回的遮罩 | 含义 | 动作 |
| --- | --- | --- |
| `0` | 仍处于隐藏态 | 什么都不做 |
| = 常规值（勾选那一刻记录的值，实测 `0x20`） | 游戏回到常规 HUD 状态（界面关了/栈被重建） | **重新隐藏** |
| 含常规值以外的位（如 `0x420`） | 游戏主动显示了额外图层（呼出界面/UI 模型） | **放行**并记一行日志 |

想"连菜单也藏"：`-Id 66 -A0 1` 切严格模式（无论读到什么都压回 0）。

### 4.5 失效与兜底（已实现）

| 情况 | 行为 |
| --- | --- |
| 取消勾选 | 立即 `Remove` + 让游戏重算；仍为 0 则直接写回常规遮罩 |
| 停止发送 / 4-关闭相机控制 | 数据流 >500ms 无新帧 → 帧末判定里立刻恢复显示 |
| 断流 3 秒（重建基线那条路） | 再恢复一次（双重保证） |
| 游戏重载场景 / 切地图 | 配置栈由游戏自己维护，切场景会重算；模块每帧读回，回到常规值就重新隐藏 |
| 找不到 UI 相机 / 两条通道都无效 | 不写任何东西，日志写明 `!! 没藏住` |
| 查看当前状态 | `tools\send_cmd2.ps1 -Id 67`（隐藏中/放行中、重申次数、放行次数） |

> **失败要开**：任何异常路径都朝"显示 UI"倒 —— 绝不把 UI 长期关在隐藏态。

## 6. v1.0.0ar：**按 ESC 全黑屏**的根因与修复（2026-09-15 实测定案）

### 6.1 现象与诊断链（每一步都有实测证据）

上一轮把策略设为**严格保持**后，用户按 ESC 得到的是**黑屏**，而不是"没有 UI 的世界"。

| # | 观测 | 结论 |
|---|---|---|
| ① | 那一刻 `MainCamera 遮罩=0x00000000`、`UICamera 遮罩=0x00000420`（位5 UI + 位10 UIPP） | 世界相机的 0 是**游戏自己写的** |
| ② | **隔离实验**：面板取消勾选、我们的配置条目已撤、保活也关 → 主相机**仍然是 0** | "ESC 熄灭世界相机"是游戏行为，与本模块无关 |
| ③ | 用保活把主相机按回 `0xAFFEDBDF`，参数全对（启用=1／深度=0／渲染到纹理=0）但**画面仍全黑** | 全黑**与 cullingMask 无关** |
| ④ | 用户目视：原生 ESC 界面的背景**就是游戏世界画面**（冻结/模糊） | 那一刻屏幕上的世界不是主相机画的 |
| ⑤ | 掩码探位（指令 65 `-A3`）：只渲染**位5** → 界面消失（黑底 + 中央一块地图样元素 + 部分光效残留）；只渲染**位10** → 界面**原封不动** | **ESC 的"菜单 + 那幅世界画面"是同一张层 10（UIPP）合成图**，掩码**拆不开** |
| ⑥ | 写 `Camera.clearFlags=3(Depth)` → **仍全黑**；写 `enabled=false` → **世界画面立刻露出来** ✓（用户当场确认） | 根因 = **遮罩=0 的相机照样执行清屏** |

> ⑤ 的推论要单独记住：**"只藏 ESC 菜单、留下那幅世界画面"在 cullingMask 层面做不到** ——
> 菜单与背景是同一张合成图上的像素。（第三档策略 `-Id 66 -A0 2` 就是为验证这一点加的，实测无效。）

### 6.2 根因

ESC（时停）界面态下，**UICamera（深度 2，排在主相机深度 0 之后）每帧把主相机已经画好的世界擦掉**，
于是画面看起来像"世界没渲染"，其实是"**画了又被擦**"。本作是自定义渲染管线（`HG.Rendering`），
**`Camera.clearFlags` 能读能写但不被采纳**，所以只能靠"让这台相机彻底不工作"来阻止清屏。

### 6.3 修复（模块 1.0.0ar）

1. **`ui_hide_disable_uicam`（默认 `true`）**：勾选"隐藏游戏 UI"时把 UI 相机 `enabled=false`
   （既不画也不擦），还原时写回原值，并每帧重申（防游戏自己打开）。状态行新增
   `UI相机=禁用(重申 N 次)`。
2. **`ui_hide_world_keepalive`（源码默认 `false`，本机 ini 为 `true`）+ 指令 73**：帧末发现主相机
   被游戏关掉就按回期望遮罩（= `GetMainCamDefaultCullingMask() & ~清位`）。
   **闸门：只在勾选隐藏 UI 时触发**（没勾选时一次都不碰主相机）；**绝不写 0**；
   隐藏结束/关闭保活时用 `_UpdateMainCamCullingMask()` 交还游戏重算。
3. 两条合起来 = **"ESC 时也能看到时停的世界画面，且画面里没有 UI"**（用户已目视验收）。

> 现场证据（日志）：`世界保活: 主相机 0x00000000 -> 已按回(按回 0xAFFEDBDF, 第 1/2 次)` ——
> 只按回 **2 次**，说明游戏只在状态切换时写了一次 0，**不是每帧对抗**。

### 6.4 遗留

位 5 上还留着"中央一块地图样元素 + 部分光效" —— 说明还有少量 UI **不在 UI 相机上**
（可能是另一个相机，或 Screen Space-Overlay 画布）。要彻底去掉这一撮，需要再定位它的宿主。

### 6.5 手动验证用的指令（v1.0.0ar）

```powershell
tools\send_cmd2.ps1 -Id 74 -A0 2 -A1 30            # 禁用 UI 相机 30 秒(到期自动还原) —— 应看到世界画面
tools\send_cmd2.ps1 -Id 74 -A0 1 -A1 30            # 只写 clearFlags=Depth —— 预期仍全黑(证明管线不采纳它)
tools\send_cmd2.ps1 -Id 74 -A0 0                   # 还原
tools\send_cmd2.ps1 -Id 73 -A0 1                   # 开主相机保活(仍需勾选隐藏 UI)
tools\send_cmd2.ps1 -Id 65 -A0 1 -A2 20 -A3 1024   # 位探位: UI 相机只渲染层10(UIPP)
tools\send_cmd2.ps1 -Id 65 -A0 1 -A2 20 -A3 32     # 位探位: UI 相机只渲染层5(UI)
```
