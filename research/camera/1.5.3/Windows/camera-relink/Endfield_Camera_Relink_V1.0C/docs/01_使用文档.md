# EndfieldCameraLink 使用文档

> 面向使用者。想看内部原理请看 `04_架构与协议.md`。

---

## 一、它是怎么连起来的

```
┌─────────────────┐        共享内存          ┌──────────────────────┐
│  Blender        │  EndfieldCameraBridgeV1  │  终末地游戏进程        │
│  Endfield Camera│ ───────────────────────► │  EndfieldCamLink.dll │
│  Bridge 插件     │   128 字节/包, 60 包/秒   │  (注入在帧末运行)      │
└─────────────────┘                          └──────────┬───────────┘
                                                        │ 走游戏自身接口
                                                        ▼
                                          CameraManager / CameraUtils
                                          SnapshotCameraController
```

- **Blender 插件**每帧把相机参数写进一块命名共享内存
- **注入模块**在游戏每帧的末尾读出这些参数，调用游戏自己的相机接口应用
- 全程不写游戏目录、不做内存扫描

三道链路各自独立，任何一个不通其他仍可用：

| 链路 | 载体 | 需要的准备 |
|---|---|---|
| 焦距 / 光圈 / 对焦距离 | 共享内存 | Blender 在发送 + 已武装 |
| 相机位置 / 朝向 | 共享内存 | Blender 在发送 + 已武装 + `pose_mode=3` |
| 官方自由相机开关 | UDP 指令 | 无（随时可用） |

## 二、安装（只需一次）

**双击包根目录的 `相机控制台.cmd`** → 菜单 **[1] 安装配置**。

脚本会：

1. 探测游戏路径（各盘符的 `Hypergryph Launcher\games\Endfield Game\`、注册表卸载项）
   与 Blender 路径（常见安装位置、PATH），写入 `paths.ini`
2. 把 Blender 插件装到用户插件目录
   `%APPDATA%\Blender Foundation\Blender\<版本>\scripts\addons\endfield_camera_bridge\`
3. 自检包内组件是否齐全

**不需要管理员权限**（游戏侧只在运行时需要）。
**安装时不会创建任何桌面快捷方式** —— 全部操作都在 `相机控制台.cmd` 里；
真想要桌面图标的话，控制台菜单 **[0]** 可以按需建一个。

命令行等价：`powershell -ExecutionPolicy Bypass -File install\console.ps1 -Action install`

> **升级到新版也是同一条命令。** 新版压缩包覆盖旧目录后，再跑一次菜单 **[1] 安装配置** 即可 ——
> 它会重探路径、整棵覆盖 Blender 插件、重写 `package_path.txt`、补齐包内 `presets\`，
> 并检查旧版残留。**不需要卸载旧版。**
> 唯一要求：升级前**先退出游戏**（DLL 被占用覆盖不进去）**和 Blender**（内存里是旧插件）。
> 详见 `08_升级与旧版迁移.md`。

如果自动探测失败，手工编辑 `paths.ini`：

```ini
game_exe=D:\Hypergryph Launcher\games\Endfield Game\Endfield.exe
launcher_exe=D:\Hypergryph Launcher\Launcher.exe
blender_exe=C:\Program Files\Blender Foundation\Blender 5.2\blender.exe
```

路径含空格**不需要**加引号。

**Blender 插件是全自动安装的**，包括"启用"这一步：

1. 复制插件文件到 `%APPDATA%\Blender Foundation\Blender\<版本>\scripts\addons\endfield_camera_bridge\`
2. 后台启动一次 Blender，调用 `addon_utils.enable(default_set=True)` 并保存偏好设置，
   让插件**真正被勾选**（否则只复制文件，你还得手工去偏好设置里勾）

所以正常情况下你**不需要手动做任何事**。安装输出会明确写出结果：

```
[OK] Blender 5.2  ->  C:\Users\...\Blender\5.2\scripts\addons\endfield_camera_bridge
[OK] 插件已启用, 偏好设置已保存 —— 无需再手工勾选。
```

**唯一例外**：如果安装时 **Blender 正开着**，脚本会跳过自动启用并提示你，原因是
正在运行的 Blender 退出时会回写偏好设置、把这次改动覆盖掉。此时两种处理：

- **关掉 Blender，重跑一次控制台菜单 [1] 安装配置**（推荐，会全自动完成）
- 或者手工勾选：`编辑 > 偏好设置 > 插件` → 搜索 `Endfield` → 勾选 **Endfield Camera Bridge**
  （勾选一次即长期记住）

**如果偏好设置里搜不到插件**，用 ZIP 方式：
`偏好设置 > 插件 > 从磁盘安装...` → 选择 `blender_addon\endfield_camera_bridge.zip` → 勾选启用。

## 三、每次使用的完整流程

装好之后，日常使用就是**打开包根目录的 `相机控制台.cmd`，按菜单序号操作**：

| 顺序 | 控制台菜单 | 什么时候 |
|---|---|---|
| 1 | **[2] 启动游戏并注入模块** | 每次开始前（会弹 UAC，点"是"） |
| 2 | **[3] 武装相机** | **进入游戏世界之后** |
| 3 | Blender 里点 **▶ 开始实时发送** | 最后 |

> 包根目录只有 `相机控制台.cmd` 这一个启动器 —— 所有动作（安装 / 启动注入 / 武装 / 关闭 /
> 日志 / 对齐原点 / 重建 / 状态 / 装插件 / 按需建快捷方式）都在它的菜单里。
> 也可以跳过菜单直接调用：`install\console.ps1 -Action <install|launch|arm|stop|status|reset|log|addon|rebuild|shortcut>`。

### 步骤 1 · 启动游戏并注入

在控制台里选 **[2] 启动游戏并注入模块**。

- 会弹出 **UAC**，请点"是"（游戏清单要求管理员权限，注入器必须同权限）
- 脚本会**挂起启动**游戏 → 注入模块 → 恢复运行
- **顺带把 Blender 调成 120 帧拍摄状态**（0.2.4 起）：
  - 检测到 Blender 正在运行 → 直接把它的**输出帧率**与**发送频率**都设成 120（0.25 秒内生效，不用点面板）；
  - 没检测到 → **先写好设置令牌再启动 Blender**，插件一加载就自动应用（帧率 120 / 发送 120 / **自动开始发送**）；
  - 想单独用或改数值：
    ```powershell
    powershell -ExecutionPolicy Bypass -File tools\ensure_blender.ps1            # 默认 120 / 120
    powershell -ExecutionPolicy Bypass -File tools\ensure_blender.ps1 -Fps 60 -Rate 60
    powershell -ExecutionPolicy Bypass -File tools\ensure_blender.ps1 -Scene "D:\my.blend"   # 启动时打开指定工程
    ```
  - ⚠️ Blender 本来没在运行时，脚本只能把它启动到**新场景 / 启动文件** ——
    **未保存的工程不会自动恢复**；要接着做上一个工程，请用 `-Scene <你的 .blend>`。

**验证**：控制台菜单 **[5] 查看运行日志**，应能看到：

```
已挂上 il2cpp_init_utf16 钩子
自举线程已附加到 IL2CPP 域 (thread_attach)
使用主锚点 CameraManager.TailLateTick
Ready: 相机链路已挂载 (hook ok, UDP 端口 9601)
成功挂上 Cinemachine.CinemachineBrain.LateUpdate -> pose_mode=3 可用
```

> **不要从启动器直接点开始游戏**——那样模块不会被加载。
> 如果游戏卡在启动前握手（进程起来了但一直没有窗口、`Player.log` 为空），
> 用命令行加参数重试先拉起启动器初始化 ACE：
> ```powershell
> powershell -ExecutionPolicy Bypass -File tools\launch_game.ps1 -StartLauncher -ForceKill
> ```

### 步骤 2 · 进入游戏世界

正常走到能自由行动的状态。**标题/加载画面下无法武装**（拍照相机尚未创建）。

### 步骤 3 · 武装相机（**每次进世界都要做**）

在控制台里选 **[3] 武装相机**。

脚本会问一句「是否同时开启位置跟随」，默认开启（回车即可）。
然后依次做五件事：

| 步骤 | 内部动作 | 作用 |
|---|---|---|
| 1/5 | `ToggleSnapshotCamera(true,false)` | 取得**游戏拍照相机实例** → 光圈/对焦的载体 |
| 2/5 | `OpenMarketingCamera()` | 打开**官方自由相机**（游戏内自由飞行视角） |
| 3/5 | 刷新实例 | 真正把营销相机实例取回来（**必须这一步**） |
| 4/5 | `pose_mode=3` | 位姿写入挂到 Cinemachine 之后 |
| 5/5 | 打印契约状态 | 报告各实例是否就绪 |

**验证**：控制台菜单 **[5] 查看运行日志** 里 `snapshot=` 与 `marketing=` 后面都不能是 `0`：

```
[gamesys] 契约: ... marketing=000000149b392bd0 snapshot=000000149b577b80
```

> 只想要焦距/光圈、不想让 Blender 控制相机位置？
> 命令行：`powershell -ExecutionPolicy Bypass -File tools\arm_lens.ps1 -NoPose`

### 步骤 4 · Blender 里开始发送

1. 3D 视图按 **`N`** → 点侧栏 **Endfield Camera** 标签
2. 面板最上面 `Camera` 下拉框 → **选中你的相机**（场景里没有就先 `添加 > 摄像机`）
3. 参数：**`发送频率` 拉到 240 以上（≥ 游戏帧率的 2 倍；面板上限 1000）**、`位置比例 1.0`
   —— 频率必须 ≥ 游戏帧率的 2 倍，否则高强度运镜会抽动（原因见 `docs\03_故障排查.md` §9）
4. 点 **▶ 开始实时发送** → 底部 `状态：` 变成 **正在发送**

之后你在 Blender 里改相机参数，游戏画面实时跟随。

> 用控制台菜单 **[2] 启动游戏并注入模块** 时，插件会被自动调成 **输出帧率 120 / 发送频率 120 / 自动开始发送**
> （见步骤 1 的说明），所以这一步通常不需要手动点。
>
> ⚠ **但这仍然是 1× 采样**：游戏 120 fps 时，120 Hz 的发送会因相位漂移漏帧 →
> 高强度运镜抽动（见 `docs\03_故障排查.md` §9）。**拍高强度运镜前请把发送频率手动拉到 240 以上。**
> （把启动令牌的 120 改成更高属于后续可选改动，尚未实施；面板上限自插件 0.3.7 起是 **1000**。）

### 步骤 5 · 用「运镜预设」一键生成镜头（0.3.0 起）

侧栏 `N` → **运镜预设** 框 → 选一个预设 → **生成这个运镜**。
插件会读取预设文件夹里的 `.py` 脚本并在当前相机上**新建独立 action** 写入关键帧（不动你原有动画，
出错 `Ctrl+Z` 可整体撤销）。细节与"怎么写自己的预设"见 **`docs\07_运镜预设.md`**。

## 四、Blender 侧详解

### 插件面板

| 控件 | 含义 | 建议 |
|---|---|---|
| `Camera` | 要发送哪个相机（即场景活动相机） | 选你的拍摄用相机 |
| `发送频率` | 每秒发多少包（**1–1000**，插件 0.3.7 起；旧版是 1–240） | **≥ 游戏帧率的 2 倍**：游戏 120 fps → 240（实测够用）；要留余量可到 360~480。过低会在高强度运镜时抽动（见 `docs\03_故障排查.md` §9）。注意上限只是"允许设到多少"：Blender 定时器受 UI 事件循环调度，1000 Hz 实际达不到 |
| `位置比例` | 1 Blender 单位 = 多少游戏米 | 保持 1.0 |
| `暂停游戏原相机控制` | 预留开关（当前游戏侧不读该标志） | 保持默认勾选 |
| `▶ 开始实时发送` / `⏸ 停止` | 开始/停止发送 | 拍完请点停止 |
| `发送当前帧` | 只发一帧 | 调单个参数时用 |
| `状态：` | 运行状态文本 | 必须是 **正在发送** |
| `通道：` | 共享内存名 `EndfieldCameraBridgeV1` | 不用改 |

### 相机参数（中文界面路径）

选中相机 → 属性面板点**绿色相机图标**（`物体数据属性`）：

| 英文 | 中文 | 作用 |
|---|---|---|
| `Focal Length` | 焦距 | 控制视场角（长焦/广角） |
| `Sensor Width/Height` | 传感器宽度/高度 | 参与焦距→FOV 换算 |
| `Clip Start/End` | 裁剪起点/终点 | 已读入，暂未下发 |
| `Depth of Field` | 景深 | 见下一节 |

相机位置与朝向：3D 视图按 `N` → 「条目」标签 → 「变换」→「位置」/「旋转」。

## 五、对焦点怎么调

### 方式 A · 手动对焦距离

1. 选中相机 → 属性面板切到**绿色相机图标**（`物体数据属性`）
2. 展开 `Depth of Field`（景深）→ **勾选 `Use Depth of Field`（启用景深）**
   ⚠️ 不勾的话景深数据不参与，光圈和对焦都不会生效
3. 设 `Focus Distance`（对焦距离，单位**米**）→ 实时送到游戏
4. `Aperture ▸ F-Stop`（光圈 ▸ 光圈系数）控制虚化强度
   - 实测：`f/1.4` 背景明显虚化、`f/16` 全画面清晰

### 方式 B · 用对焦物体自动跟焦（拍片推荐）

同一面板 → `Focus Object`（对焦对象）下拉框 → 选一个物体（角色、道具等）。

之后 `Focus Distance` 会变成由 Blender 自动计算（= 相机到该物体的距离）。因为插件读的正是
`cam.dof.focus_distance`，所以你**让物体或相机移动时对焦点会自动跟着走**——等于免费得到一个跟焦器。

### 要点

- `Focus Distance` 两边单位都是米，**1:1 对应**，不需要换算
- 景深依赖游戏侧快照相机实例 → **每次进世界都要先 `arm_lens.ps1`**
- 虚化不明显时依次检查：①`Use Depth of Field` 是否勾选 ②F-Stop 是否够小（1.4~2.0）
  ③对焦距离是否与画面主体距离同量级（设成几十米而主体在 3 米处 → 几乎全清晰）

### v1.0.0as：光圈现在**在自由相机里直接生效**，还有个「修复虚化」按钮

**以前的行为**：光圈只在**进过官方相机（拍照/营销）之后**才生效。**现在不需要了** —— 根因是
`SetAperture/SetFocusDistance` 只"写数值"，必须再调一次 `ApplySnapshotDofSettings()` 才会把它**挂到主相机**上
（那是"落地"的一步，只有游戏自己进拍照模式时才会做）。模块现在：**每次改完光圈/对焦都补一次 Apply**，
并且每 3 秒保活重施加一次（ini `lens_dof_keepalive=false` 可关）。

**唯一还需要你动手的情况**：进过一次官方相机再退出后，游戏会**换掉那个快照相机控制器**，模块手里那个就陈旧了
（表现为：光圈怎么拖都没反应）。这时点面板「镜头模式」区里的 **「修复虚化」** 按钮即可（= 指令 78：重新取实例 +
把当前 f 值/对焦距离喂回去 + Apply）。实测：点完虚化立刻回来。

顺带两条实测记录（2026-09-15）：
- **写入门槛/节流**：镜头参数最多 400ms 写一次，光圈 0.05 / 对焦 0.02m / 焦距 0.3mm 以内不算变化 ——
  这是为了修"拖动光圈时画面抽动"（此前一秒内会写 6~7 次）。
- **双向对照**：`f/1.4` 明显虚化、`f/22` 几乎全清楚（长焦 170~190mm 时最明显）。

## 六、位置与朝向的使用规则

### 两种链路（模式）

两种模式在**插件面板**里选（N 侧栏 → Endfield Camera → 镜头模式）；控制台菜单 **[3] 武装相机** 会自动读面板
的选择并按对应模式武装，不需要另加参数。

| 模式 | 行为 | 用途 |
|---|---|---|
| **定镜头** | 武装那一刻取一次角色坐标并**冻结**，此后不再用角色坐标干预相机 —— **相机钉在世界上那一点不动** | 拍固定镜头：角色在画面里表演/走位，相机不动 |
| **随角色镜头** | **每帧读实时角色坐标**，相机始终保持在"角色 + Blender 偏移"的位置上 | 跟拍：角色移动时保持构图 |

两者**都由模块每帧绝对写相机变换**（`pose_mode=3`）—— 这条路对**游戏自身的相机状态与鼠标都免疫**
（实测：进入游戏自带相机模式、或晃鼠标，画面都不动）。区别只在"游戏侧原点是常量还是实时值"。

- 随角色模式会**关闭官方自由相机**：自由相机开着时 `vcamFollow` 读不到，实时角色坐标就取不到。
- 读不到实时值时，会退回"武装时冻结的值"，并在日志里写明 —— 相机不会乱跳，但那一段时间不跟随。
- `pose_mode=4`（发相机偏移、让游戏自己摆相机）保留为**实验路径**，用
  `tools\send_cmd2.ps1 -Id 22 -A0 4` 手动进入。它的问题：偏移基准 P0 与坐标系 R 都在游戏手里，
  **鼠标一动基准就漂**（实测），且沿视线方向受机架距离限制 —— 因此不作为正式链路。

两条模式**共用同一套 Blender 侧坐标与同一份运镜脚本** —— 切换模式不需要改任何 Blender 工程。

### 隐藏游戏 UI（拍摄用，v0.3.8 起）

面板「镜头模式」下面有一个复选框 **隐藏游戏 UI（拍摄用）**。勾上后画面里的 HUD（血条、技能栏、
小地图、任务提示等）会整体消失，只留世界画面；取消勾选立刻恢复。

| 项目 | 说明 |
| --- | --- |
| 原理 | 游戏里 HUD 由**一台独立的 UI 相机**（`UICamera`，只渲染**层 5**）绘制，世界由 `MainCamera` 绘制且它的遮罩**不含层 5** —— 所以把 UI 相机的渲染遮罩压成 0，世界画面完全不受影响 |
| 通道 | 用**游戏自己的接口**：`AddUICamCullingMaskConfig("ECLHideUI", 0)` + `_UpdateUICamCullingMask()`；恢复 = `RemoveUICamCullingMaskConfig("ECLHideUI")`（让游戏自己重算，不会残留） |
| 不碰什么 | 不改任何 UI 的逻辑状态（不做 `SetActive(false)`/`canvas.enabled=false`），不合成按键，不做截图/水印处理 |
| 键位与战斗 | **完全不受影响**：实测隐藏期间移动、跑动、普通攻击、技能都照常（这一点与"原生相机按 X 隐藏 UI"相反 —— 那条会让很多键位失效） |
| **菜单（ESC）** | **默认"尊重游戏"**：你主动呼出的界面（ESC 菜单/背包/设置）**正常可见**，关掉后会重新隐藏。代价：战斗中游戏往 UI 相机配置栈加层时也会触发放行，HUD 可能短暂回来。想"连菜单也藏"：`tools\send_cmd2.ps1 -Id 66 -A0 1`（或 ini `ui_hide_strict=true`） |
| **ESC（时停）时也要看到世界**（v1.0.0ar，本机 ini 已开） | 勾选隐藏 UI 后按 ESC：**画面里没有 UI，而且是时停/静止的世界画面**（不是黑屏）。由两条配合实现：① `ui_hide_disable_uicam=true` —— 隐藏时把 UI 相机**整体禁用**（只压遮罩不够：**遮罩=0 的相机照样清屏**，会把主相机画好的世界擦黑）；② `ui_hide_world_keepalive=true` —— 游戏在 ESC 时会把世界相机遮罩写成 0，保活在帧末按回。**这两条只在勾选隐藏 UI 时生效**；不勾选时一次都不碰相机 |
| **世界空间的 UI**（怪物血条/状态条/角色体力条） | 它们在**层 16 = WorldUI**，由 **MainCamera** 渲染，压 UI 相机盖不住 —— 已实测确认（指令 70 的图层名表）。用指令 71 清掉这一层（下面单列一节） |
| 断流 | 数据流中断 >500ms 立刻恢复显示（失败要开，绝不把 UI 关死） |
| 查看状态 | `tools\send_cmd2.ps1 -Id 67` 打印当前状态（隐藏中/放行中、重申次数、世界清位、**保活按回次数**、**UI 相机是否被禁用**） |

> 提示：勾选状态随包发到模块（共享内存标志位 6），所以**武装/开始发送后**才会生效；
> 停止发送或关闭相机控制会自动恢复显示。

#### 连怪物血条/状态条也要藏掉（世界空间 UI）—— **默认已经替你做好了**

**已实测确认（2026-09-15）**：怪物血条/状态条/角色体力条这类"跟着角色或怪物跑"的 UI 在
**层 16 = WorldUI**，由 `MainCamera` 渲染（所以压 UI 相机盖不住）。默认值
`ui_hide_maincam_clear_bits=65536`（位 16）已经打开 —— **勾上「隐藏游戏 UI」时它会和屏幕 HUD 一起消失，
而世界画面（角色/怪物/建筑/地形）完好无损**。下面这些步骤只在你想调整/排查时用：

```powershell

tools\ui_probe.ps1 -Step world -Hold 15      # ② 只清 位16 WorldUI, 15 秒后自动还原 —— 看效果
tools\ui_probe.ps1 -Step world2 -Hold 15     # ③ 清 位16+位15(连"按F交互"提示一起)
tools\ui_probe.ps1 -Step worldkeep           # ④ 确认后设为持续(勾选隐藏 UI 时一并生效)
tools\ui_probe.ps1 -Step worldoff            # 撤销: 主相机立刻恢复
```

```powershell

tools\send_cmd2.ps1 -Id 71 -A0 65536          # 持续
tools\send_cmd2.ps1 -Id 71 -A0 0              # 撤销
```

```

### 位置：以「参考物件」为原点（**固定用法**）

在 Blender 场景里放一个**参考物件** —— 就是新建场景自带的那个方块 **`Cube`**（名称必须是
`Cube`），把它当成**游戏里角色的替身**：角色站在哪，方块就摆在哪（原地、地面高度即可，不必精确）。

```
游戏目标位置 = 游戏原点 + (Blender 相机位置 − Cube 位置)
```

- **游戏原点** = 武装那一刻游戏相机的位置（+ 一次性校准量），它是"相机相对角色的位置"，
  所以方块与相机的相对摆放会 **1:1** 出现在游戏里。
- 相机相对方块摆在哪（方块前方 3 米、高 1.7 米），游戏里就相对角色摆在哪。
- **v0.3.9 起面板上不再有"用不用参考物件"的开关与选物框** —— 这一条链路只有绝对锚点这一种
  可靠用法（增量锚点会随武装时刻漂），留开关只会让人不知不觉用错模式。面板上只留一行状态：
  `位置原点: Cube → (x, y, z)`；场景里没有 `Cube` 时那行会变红提示（此时退回旧的增量锚点）。
- 运镜预设里的"锚点"也用的是同一个 `Cube`（`EFBridge.anchor()`）。

### 武装时自动归零（固定行为）

武装时由控制台菜单 **[3] 武装相机** 通过令牌触发，**不是面板上的开关**（v0.3.9 起面板上那句固定说明
文本也去掉了，行为不变）：

- **武装时自动水平归零**：保留水平朝向角，俯仰/滚转归零
- **武装时位置归零到 (0,0,0)**：把相机位置设为原点 → 于是 `(0,0,0)` 就是游戏里的角色点

> 单次豁免：`tools\arm_lens.ps1 -NoZero`；`-NoReset` 可跳过自由相机复位。
> 相机有关键帧时，归零结果会在播放动画时被关键帧覆盖（属预期）。

### 武装时序（为什么这样排）

控制台菜单 **[3] 武装相机** 现在按下面的顺序执行，目的是让**原点确定且干净**（早期偏差 2.2 米就是抓早了）：

```
27 取快照实例(进拍照模式) → 2 开自由相机 → 10 刷新实例
→ 等 1.5s               让拍照模式的相机混合/稳定
→ 21 复位自由相机位置    让"游戏自己摆的机位"确定
→ 22 a0=3 开写位姿       模块开始每帧缓存"引擎位姿" = 游戏自己的机位
→ 等 1.0s → 34 重取基线  原点 = 游戏自己刚摆好的那个机位
→ 9 打印状态 → 令牌通知插件（水平归零 + 位置归零）
```

### 朝向：完全由 Blender 决定

```
游戏相机朝向 = 你 Blender 相机的朝向（同一个物理方向）
```

位置留在游戏里（不会被搬到关卡外），朝向完全交给 Blender。这样两边相机的**本地轴一一对应**：
你在 Blender 里绕相机的本地 X / Y / Z 转，游戏相机就绕自己的本地 X / Y / Z 转，
俯仰不会带出滚转，三个轴不会互相串。

> **关于数值**：Unity 是左手系、Blender 是右手系，同一个物理转向在两边的欧拉角符号是**相反**的。
> 例如 Blender 里 `旋转 X = +20°` 是抬头，游戏里的等价数值是 X = −20°（同样是抬头）。
> 所以别指望两边数字一样，只看画面里的转向是否一致。

### 三条硬性规则

1. **位移幅度要小**（几米 ~ 几十米）。
   相机位置本来由游戏逻辑（角色位置、地形、碰撞）决定，强行搬到很远的地方通常会落进地形内部，
   表现就是画面变灰/虚空。（`pose_max_offset` 默认 800 游戏单位做限幅保护）

2. **保持发送不中断**。

   | 情况 | 行为 |
   |---|---|
   | 发送中偶发丢帧（< 3 秒） | 保持当前位移，画面不跳 |
   | 停止发送 > 500 毫秒 | 停止写位姿，**相机交还游戏自己控制**（安全阀，防止卡在关卡外无法恢复） |
   | 停止发送 > 3 秒后恢复 | **基线重新对齐**（当前 Blender 位置变成新原点，原位移归零） |

3. **移动方法建议用数值输入**（可控、可复现）：
   选中相机 → `N` → 「条目」→「变换」→「位置」→ 点数字框输入 `当前值 + 3` → 回车。

### 让 (0,0,0) 正好落在角色身上（原点校准）

默认的"游戏侧原点"是**武装那一刻游戏相机的位置**，它和角色本身有少量偏差，
所以 Blender 相机在 (0,0,0) 时游戏相机不会正好与角色重合。两种情况：

**① 一次性校准（最省事，推荐先试）**

```powershell
tools\calibrate_origin.ps1
```

标准流程：

1. 武装相机
2. 把 Blender 相机位置设为 `(0,0,0)`（参考方块也应在原点）
3. 用 Blender 把游戏相机挪到**正好与角色重合**
4. 运行 `tools\calibrate_origin.ps1`（= 指令 41）—— 模块把当时的位移吸收成"原点修正量"
5. 把 Blender 相机位置设回 `(0,0,0)` —— 现在它正好落在角色身上 ✓

> 第 4 步瞬间画面会跳一下，属于预期（原点即刻生效）；第 5 步就回到你刚对准的位置。
> 日志 `[origin]` 行会打印修正量，把它写进 `game_mod\EndfieldCamLink.ini` 的
> `pose_origin_dx/dy/dz` 即可跨会话保留。

**② 直接取游戏的角色锚点（若候选可用，则完全不用手校准）**

```powershell
tools\send_cmd2.ps1 -Id 43            # 看 4 个候选各自的坐标
tools\send_cmd2.ps1 -Id 42 -A0 1      # 选中看着对的那个(1..4)
```

| a0 | 候选来源 |
|---|---|
| 0 | 武装那一刻相机位置（默认，需配①的修正量） |
| 1 | 当前 vcam 的 Follow 目标（多数情况就是角色） |
| 2 | 当前 vcam 的 LookAt 目标 |
| 3 | 当前激活控制器的 cameraTrans |
| 4 | 引擎相机位置 − 原生相机偏移 |
| **5** | **引擎相机位置（游戏自己的机位）** —— v1.0.0ab：以游戏当前机位为原点、只叠加 Blender 偏移，从而继承游戏的逐帧平滑/跟随阻尼；**不叠加锚点微调量**；只在"游戏相机确实在跟随角色"时有效 |

持久化：`game_mod\EndfieldCamLink.ini` 里 `pose_anchor_source=1`（或 2/3/4，也可写 `enginecam` 等名字）。

> **什么时候用 5**：随角色模式下，角色**走动/跳跃**时画面出现"小幅度、随角色速度增大"的抖动
> （角色静止不抖、定镜头不抖）—— 这是锚点时间粒度问题，换成来源 5 可把游戏那层平滑继承过来。
> 一条指令即可切回：`-Id 42 -A0 1`（vcamFollow）或 `-A0 0`（武装点）。详见 `docs\03_故障排查.md` §9 与
> `docs\04_架构与协议.md` 的"来源 5"小节。

                          ; 指令 40 可热切换

## 十、性能与注意事项

- **发送频率**：**往高了设（面板上限自插件 0.3.7 起是 1000）**。它不是"够用就行"的参数：
  模块是**按"有没有新包"来写的**——某游戏帧若没有新包，那一帧就不写位姿、直接露出游戏自己的相机位姿。
  包率一旦低于（或只是等于）游戏帧率，相位漂移与定时器抖动就会让部分帧丢包，
  表现为**高强度运镜时画面抽动**（幅度随运镜幅度增大）。设成 ≥2× 游戏帧率后，单帧丢包概率趋近于 0。
  游戏 120 fps → **240**（实测够用）；要留余量可以到 360~480。
  （早期文档写的"60 足够、卡顿就降到 30"是错的，已更正。）
  注意两点：① 调高包率**几乎不增加游戏侧开销** —— 模块每渲染帧只读一次共享内存，多出来的包只是被覆盖；
  ② 上限只是"允许设到多少"：Blender 定时器由 UI 事件循环调度，1000 Hz（1 ms）**实际达不到**，
  面板值只是目标值，且包构建成本随频率线性上升 —— 别把上限当默认。
  旧版（插件 ≤0.3.6）上限是 240，填 360 会被静默夹到 240。
- **多显示器/独占全屏**：无影响，本工具走的是游戏内部相机接口，不是窗口捕获。
- **游戏更新后**：模块靠**运行时按名字解析**游戏接口，小版本更新一般无需重建。
  若日志里出现大量 `MISS`，再按 `02_其他电脑安装方案.md` 重建。
- **不要同时开两个 Blender 发送**（画面会来回跳）。
- **长时间拍摄**：每跑几小时建议重启一次游戏，重置注入状态。
