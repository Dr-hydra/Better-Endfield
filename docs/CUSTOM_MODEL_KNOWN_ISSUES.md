# CustomModel 已知问题

## CM-001：配队界面偶发模型部位缺失

- 记录日期：2026-09-16。
- 状态：偶发，暂时无法复现；根因未确认，未标记修复。
- 处理决定：按用户要求独立登记，暂停主动复现与诊断；后续自然出现时再根据证据继续调查。
- 发现环境：资源重建版本 B5-sustain-lod0；调查期间部署过 B6-lod0-skin-field-audit。开发收尾后 B6 检测代码已撤除，正式版保留 B5 的功能行为。

### 已知现象

用户在配队界面观察到管理员眼睛缺失。切换角色不能恢复，退出并重新进入配队界面后恢复。用户认为重入刷新了 Mesh，但尚无对应的异常前后对象身份记录证明是否确实重建了 Mesh。

目前无法稳定复现，首次进入或其他触发条件不明。用户强调 Mesh 损坏可能随机影响任意部位，因此排查范围应覆盖全部自定义 Mesh，不能只针对眼睛。本轮明确报告的可见症状是管理员眼睛缺失，不能扩写为已观察到所有角色或部位均异常。

暂时的恢复方式：退出并重新进入配队界面，本次反馈中有效。

### 已核查内容与证据边界

1. 新 Mesh 的 `m_BonesPerVertex` 仍在几何和 bindposes 上传前，从对应原版 Mesh 复制。字段偏移通过两个一致的原生序列化函数解析，当前客户端结果为 `0x1C8`，不是运行时固定偏移。
2. 已有日志里管理员眼睛 C7 的源字段值为 1，其他部件按各自原版为 1 或 4；初始化读回通过，上传后的字段不一致会拒绝提交。本轮没有记录到该阶段的字段校验失败。
3. 原检查止于上传阶段，不能证明游戏完成资源交付和后续使用时字段仍正确，也不能据此排除后续生成独立 Mesh、绑定变化或其他渲染状态问题。
4. `m_BonesPerVertex` 异常是待验证方向，不是本问题已经证实的根因。重入后恢复也不能单独证明 Mesh 字段损坏。

### 曾部署的观察能力（收尾时已撤除）

B6 在已验证的 B5 LOD 行为上增加只读检查，覆盖所有已登记的自定义 Mesh。日志标识为 `Mesh skin audit`，记录资源根、部件、Mesh/renderer 身份、对应原版字段预期值、当前字段、绑定及可见状态。

检查发生在提交、原交付回调返回、重复交付及每秒维护阶段；维护仅在状态变化时输出。观察使用弱引用，不自动改写字段、重绑或重建 Mesh。

范围限制：自然实例共享已登记 Mesh 时，其字段变化可被观察；游戏另行生成的未登记独立 Mesh 不会自动纳入。没有异常日志不等于所有实际场景实例均正常。

只读观察的 94 项专项断言已通过。用户后续无法复现，因此尚未取得症状发生时的 B6 证据，不能将其记为问题修复或根因验证通过。

### 后续处理

不安排持续复现，不重复已经通过的世界/详情替换、LOD 和懒加载测试。后续如自然再现，保留发生时间、界面及异常部位，再根据需要恢复最小观察能力，决定针对性修复与验证。正式版已撤除 B6 跟踪，不能期待其继续输出 `Mesh skin audit` 日志。

后续测试只覆盖本次修改及直接受影响的路径，避免无变化的重复校验。
