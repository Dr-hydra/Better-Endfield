# 11. 开源与发布检查清单

> 用途：把"能不能发、发什么、怎么发"固化成一张表。**每次公开发版前照着打勾**，
> 尤其是本节 ①（脱敏）——一旦提交进 Git 历史，删掉文件也仍然留在历史里，只能重写历史或重建仓库。
>
> 发布形态：**源码进仓库，二进制与分发包走 Release 附件**（见 ②）。
> 许可：MIT（见 `LICENSE`）；使用边界见 `USAGE_BOUNDARY.md`；第三方署名见 `NOTICE`。

## ① 脱敏：绝不能进仓库的东西

| 打勾 | 项 | 为什么 | 处理 |
|---|---|---|---|
| ☐ | `game_mod\*.log`（`EndfieldCamLink.log` 等） | 运行期会话数据、本机路径 | `.gitignore` 已忽略；**永远不要** `git add -f` |
| ☐ | `*_camprobe.log`、崩溃报告、`%TEMP%\...\Crashes\*` | 内存/路径/堆栈信息 | 已在忽略名单 |
| ☐ | `paths.ini`、`package_path.txt` | 本机绝对路径 + Windows 用户名 | 已在忽略名单 |
| ☐ | 含 **游戏 UID / 账号名 / 好友列表**的截图与录屏 | 隐私 | 重新截图或打码后再放进 `docs\` 或 README |
| ☐ | `game_mod\EndfieldCamLink.dll`、`injector.exe` 等预编译件 | 体积 + 每次重编都会多一份历史 | 走 Release 附件（`.gitignore` 已忽略 `*.dll` `*.exe`） |
| ☐ | `dist\*.zip`、`backup\`、`build_ui\`、`build_probe\`、`obj\`、`__pycache__\` | 旧产物/编译垃圾 | 已在忽略名单 |
| ☐ | Word/PPT/图片里的**文档属性**（作者、最后修改者、公司） | docx 的 `docProps/core.xml` 会带出本机账户名 | 本项目说明文档已清理；新增办公文档请先清属性 |
| ☐ | 任何密钥、token、账号密码 | 一旦进历史就必须作废重签 | 用环境变量或本地文件（已在忽略名单外，需人工确认） |

**提交前自查命令**（应当没有任何输出）：

```powershell
git status --short                      # 有没有意外被 add 的文件
git check-ignore -v paths.ini game_mod\EndfieldCamLink.log game_mod\EndfieldCamLink.dll
git log --stat -1                       # 最近一次提交动了哪些文件
```

```powershell
# 扫一遍"疑似个人信息"关键字(按需增删)
Get-ChildItem -Recurse -File | Where-Object { $_.FullName -notmatch '\\\.git\\' } |
  Select-String -Pattern 'UID|C:\\Users\\|paths.ini' -List
```

## ② 每次公开发版的步骤

| 序号 | 动作 | 命令/位置 |
|---|---|---|
| 1 | 确认工作区干净、可编译 | `powershell -ExecutionPolicy Bypass -File source\build.ps1 -OutDir build_ui` |
| 2 | 更新 `VERSION.txt`：顶部"发布名称/包版本"+ 文末新增一条修订条目（写清改了什么、实测结论、已知代价） | `VERSION.txt` |
| 3 | 打分发包（会剔除 `paths.ini`、日志、`__pycache__`，并把 `paths.ini` 换成空模板） | `powershell -ExecutionPolicy Bypass -File install\make_dist.ps1` |
| 4 | 核对产物：`dist\<发布名>.zip` + `.sha256.txt`（记录哈希、大小、条目数） | `dist\` |
| 5 | 编译产物与源码一致性：把 zip 里的 `game_mod\EndfieldCamLink.dll` 哈希写进 Release 说明 | `Get-FileHash` |
| 6 | 提交并打 tag（如 `v1.0.0`） | `git tag -a v1.0.0 -m "..."` → `git push --tags` |
| 7 | 在 GitHub 建 Release：**把 zip 作为附件上传**，说明直接抄 `VERSION.txt` 对应条目 | GitHub → Releases |
| 8 | Release 说明里必须写：**已知问题**、**边界声明**、**SHA256**、**内部版本号对照** | — |

## ⑤ 常见坑（本项目已经踩过的）

| 坑 | 后果 | 规避 |
|---|---|---|
| 中文 `.ps1` 丢 UTF-8 BOM | 本机 ANSI 代码页是 936，`powershell.exe` 会把脚本里的中文读成乱码，甚至解析失败 | 任何脚本改完检查 BOM；`tools\fix_ps1_bom.ps1` 可批量补 |
| 把 `game_mod\` 一起提交 | 日志 + 二进制进历史，仓库膨胀且隐私外泄 | `.gitignore` 已忽略整个目录 |
| 先推上去再删敏感文件 | 历史里仍有 | 只能重写历史（`git filter-repo`）或重建仓库 |
| 分发包与源码不一致 | 用户拿到的 DLL 不是这份源码编的 | 发版步骤第 4/5 步：记录哈希 + 源码可编译验证 |
| 文档写了"已修"但代码是回退版 | 用户按文档操作却遇到崩溃 | 每次回退/改动都同步 README「已知问题」与 `docs\03_故障排查.md` |
| 把 `dist\`、`backup\` 打进仓库 | 体积大、还含旧版二进制 | 已在忽略名单；历史包放 Release 或网盘 |
