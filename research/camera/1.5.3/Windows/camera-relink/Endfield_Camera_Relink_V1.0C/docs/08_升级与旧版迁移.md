# 升级与旧版迁移 · 把新版发给"已经装了旧版"的人

> 适用：对方手上已经有**任意一个旧版本**的 EndfieldCameraLink（从 1.0.0b 到 1.0.0v 之间都算）。
> 结论先给：**新版覆盖旧目录 → 跑一次控制台 [1] 安装配置 → 重启 Blender → 照旧走 [2][3]** 就行，
> **不需要卸载、不需要手工删文件**。但有 3 件事 [1] 不会替你做，见 §3 —— 不做不会报错，
> 只会让人以为"升级完了"其实还在跑旧文件。

---

## 一、为什么只跑一次 [1] 就够 —— 它到底覆盖了什么

`相机控制台.cmd` → 菜单 **[1] 安装配置**（= `install\install_all.ps1`）本身就是**升级脚本**。
它从 1.0.0w 起会先把旧版残留检查一遍，然后按顺序重做下面全部内容：

| 步骤 | 做的事 | 对升级的意义 |
|---|---|---|
| **[0/4] 旧版残留检查**（1.0.0w 新增） | 检测旧预设目录 / 正在运行的游戏与 Blender | 这两处是升级最容易漏的地方，现在会自动提示（只提示，不删东西） |
| **[1/4] 路径探测** | 重写 `<包根>\paths.ini`（`game_exe` / `launcher_exe` / `blender_exe`） | 换机器、换盘符、游戏更新后路径变了，都会被重新探对 |
| **[2/4] 插件安装** | ① 把插件**整棵目录**复制到 `%APPDATA%\Blender Foundation\Blender\<版本>\scripts\addons\endfield_camera_bridge\`（含 `presets\` 子目录，跳过 `__pycache__`）② 写入 `package_path.txt`（告诉插件包根在哪）③ **步骤 1b**：建立并补齐 `<包根>\presets`，把 `package_dir` / `preset_dir` 写进 `paths.ini` ④ 后台启动 Blender 执行 `addon_utils.enable()` + `save_userpref()` | 旧插件被**原地整棵覆盖**（旧文件不会残留成"半新半旧"）；`package_path.txt` 指向本次解压的目录 —— 这就是"整个包随便放哪都能用"的关键 |
| **[3/4] 自检** | 组件完整性 + `paths.ini` | 缺文件（半途解压失败）会当场报红 |

> **从 v1.0.0au-fix 起，安装不再创建桌面快捷方式**（也就没有"快捷方式指向旧目录"这一类问题）：
> 全部操作都在包根目录的 `相机控制台.cmd` 菜单里。所以升级后**只要从新目录的控制台启动**，
> 就不会再出现"点开还是旧版"。真想放个桌面图标，用控制台菜单 **[0]** 按需建一个。

顺带说明：`paths.ini` 里**只有**这 5 个键是"本机专属"的（3 个路径 + 2 个包内目录），
整包分发时模板里是清空的、由对方跑 [1] 重新填；所以**覆盖旧 paths.ini 不会丢任何东西**。

## 二、`<包根>\presets` 里自己写的运镜预设会不会被覆盖？

**不会。**

- 安装脚本只**补缺失**：`<包根>\presets` 里已存在的 `.py` 一个都不动，只把缺的示例补进去。
- 插件侧还有一层保护（0.3.5 起）：随插件分发的示例预设用 `.bundled.json` 记录哈希，
  只更新"未被改过"的那些；用户改过的那份会备份到 `_bundled_backup\`，
  新版示例放进 `_bundled_new\` 让你自己比对着合并。
- 同理，面板里"预设文件夹"字段指向的任何目录，插件都不会去写。

## 三、[1] **不会**替你做、升级时必须补上的 3 件事

### 1) 升级前先退出游戏、退出 Blender

| 进程 | 不关会怎样 |
|---|---|
| **游戏**（`Endfield.exe`） | `game_mod\EndfieldCamLink.dll` 正在被进程占用 → 覆盖解压会**失败或被跳过**（仍是旧模块）；而且游戏里跑的是内存里那份旧模块。**必须退游戏 → 重新解压覆盖 → 再跑 [1]** |
| **Blender** | ① 插件装在 `%APPDATA%`，覆盖文件后**内存里还是旧插件**；② 安装脚本检测到 Blender 在运行会**跳过自动启用**（怕它退出时回写偏好设置覆盖掉本次改动）。→ 重启 Blender，或偏好设置里对本插件点一次「重新加载脚本 / Reload Scripts」 |

> 覆盖 .py 时如果文件被占用，Windows 会拒绝；实测最稳妥的顺序就是：
> **退游戏 + 退 Blender → 解压覆盖 → [1] → 开 Blender**。

### 2) 旧版的用户目录预设要清掉（只有 ≤0.3.5 的用户有）

0.3.5 及以前，运镜预设放在 `%APPDATA%\EndfieldCameraLink\presets`。
**0.3.6 起改读 `<包根>\presets`**，那个旧目录不再被读取，但里面是 0.3.0 的**老示例预设**
（正是"环绕/推拉/升降看起来有速度、角度跳变"的根源）。

- 处理：直接删掉整个 `%APPDATA%\EndfieldCameraLink\`（或改名留作备份）。
- 另外：如果对方的旧 `.blend` 场景里，面板上的「预设文件夹」字段还写着那个旧路径，
  **插件会继续用旧文件**（这个字段优先于默认目录）。把该字段清空 → 自动回到 `<包根>\presets`。
- [1] 的 [0/5] 步骤会检测并打印这个目录的完整路径，照提示删即可。

### 3) 自己改过源码 / 自己跑过 [7] 重建的人，先备份

覆盖会把 `game_mod\EndfieldCamLink.dll` 与插件源码换成分发版。
如果对方自己改过 `source\` 或 `__init__.py`，让他先把改动备份出去。
**只想正常使用的人不需要做任何事** —— 包里的 DLL 是编译好的成品，[7] 只有"想从源码重建"时才需要（要 MinGW）。

## 四、两种升级姿势

### 姿势 A（推荐）：解压**覆盖**原目录

1. 退出游戏、退出 Blender。
2. 把新版 zip 解压到**和旧版同一个目录**，提示"是否替换"选**全部替换**。
   （`paths.ini` 会被新版模板覆盖也没关系 —— [1] 会重新探测）
3. 打开包根目录的 `相机控制台.cmd`，跑菜单 **[1] 安装配置**。
4. 打开 Blender → 侧栏 `N` → Endfield Camera → 确认预设下拉栏里有 环绕/推拉/升降。
5. 照旧：菜单 **[2] 启动游戏并注入模块**（弹 UAC）→ 进世界 → 菜单 **[3] 武装相机** → Blender 点「开始实时发送」。

### 姿势 B：解压到**新目录**（旧目录留着做对照）

1. 退游戏、退 Blender。
2. 新版解压到新目录（例如 `D:\EndfieldCameraLink_1.0.0w`）。
3. 打开**新目录**里的 `相机控制台.cmd`，跑菜单 **[1] 安装配置** —— 会自动把插件重装、包根改指到新目录。
4. 之后一律用**新目录**的 `相机控制台.cmd` 启动游戏（安装不再建快捷方式，因此不存在
   "桌面图标还指着旧目录"这种坑；旧版留下的 `终末地相机 - *.lnk` 可以直接删掉）。
5. 建议：新目录确认可用后，把旧目录改名成 `EndfieldCameraLink_old`，别直接删（要回滚很方便）。

> 注意：模块日志 `game_mod\EndfieldCamLink.log` 永远只写在**本次用来启动游戏的**那个包目录里。
> 姿势 B 下如果日志还在旧目录里长，说明你启动的是旧目录的控制台。

## 五、升级后 60 秒自检（确认真的换成功了，而不是你以为换了）

| 检查点 | 应该是 |
|---|---|
| `VERSION.txt` 顶部"修订版本" | `1.0.0aa`（按实际分发版本对） |
| `<包根>\blender_addon\endfield_camera_bridge\__init__.py` 第 4 行 `"version"` | `(0, 3, 7)`（0.3.7 起发送频率上限 240→1000） |
| 该文件 SHA256 与 `VERSION.txt` 里记的一致 | 一致 = 文件没坏、没被旧文件覆盖回去 |
| `%APPDATA%\Blender Foundation\Blender\<版本>\scripts\addons\endfield_camera_bridge\package_path.txt` | 内容 = 当前包根路径 |
| Blender 预设下拉栏 | 列出 环绕 / 推拉 / 升降（来自 `<包根>\presets`） |
| 控制台 [5] 查看运行日志 | 出现 `[anchor] 冻结锚点(v1.0.0m, ...` 这类带版本号的行动说明模块是新的 |
| 生成一次运镜 | 起始/结束**不应有位置跳变**（有跳变 = 还在读 0.3.0 的旧预设文件） |

哈希核对命令（把 `<包根>` 换成实际路径）：

```powershell
Get-FileHash '<包根>\blender_addon\endfield_camera_bridge\__init__.py' -Algorithm SHA256
Get-FileHash '<包根>\game_mod\EndfieldCamLink.dll' -Algorithm SHA256
```

再和 `VERSION.txt` 的「产物与校验值」一节对照即可。

## 六、回滚

1. 退游戏、退 Blender。
2. 用旧 zip 覆盖回原目录（或把之前改名的旧目录改回来）。
3. 再跑一次 [1]，重启 Blender。
4. 模块 DLL 与插件版本是**一对**：覆盖哪个包就用哪个包里的 DLL，不存在"只换其一"的中间状态，
   也不需要卸载任何东西。

> 版本敏感提示：模块是**针对游戏 Unity 2021.3.34f5 的运行时布局**写的。
> 游戏本体更新后模块可能失效（表现：日志停在 `[hook]` 阶段 / 武装相机失败），
> 这与升级包无关，见 `docs\03_故障排查.md`。

## 七、可以直接复制发给对方的话

**A. 全新安装**

```text
1) 解压整个 EndfieldCameraLink 文件夹到非系统盘（别放进游戏目录）
2) 从邮件/网盘下载的，先右键 zip -> 属性 -> 勾"解除锁定"，或解压后跑 install\unblock_files.ps1
3) 双击包根目录的「相机控制台.cmd」-> 菜单 [1] 安装配置（探测路径 + 装 Blender 插件 + 自检）
4) 之后每次都用这个控制台：菜单 [2] 启动游戏并注入（弹 UAC 点"是"）-> 进游戏世界 -> 菜单 [3] 武装相机
   （包根目录只有这一个 .cmd；安装不会在桌面建快捷方式）
5) 然后在 Blender 里按 N -> 侧栏 Endfield Camera -> 开始实时发送
遇到问题先看 docs\03_故障排查.md
```

**B. 从旧版升级（照抄）**

```text
1) 先退出游戏，再退出 Blender（很重要：不退游戏，新的 dll 覆盖不进去）
2) 我的新版 zip 覆盖解压到你原来那个目录（提示替换就选全部替换）
3) 双击包根目录的「相机控制台.cmd」-> 菜单 [1] 安装配置 跑一次（路径/插件/预设目录都按新版重做）
4) 如果你以前用过"运镜预设"：把 %APPDATA%\EndfieldCameraLink 整个删掉
   （那是旧版 0.3.0 的示例预设，新版已经不读它了，留着反而会干扰）
5) 打开 Blender，确认 N 侧栏 Endfield Camera 里预设下拉栏有 环绕/推拉/升降
6) 照旧：控制台 [2] 启动游戏并注入 -> 进世界 -> [3] 武装相机 -> Blender 点"开始实时发送"
   （旧版建在桌面的「终末地相机 - *」快捷方式可以删掉了：新版不再用它们）
```

**C. 完整性**

```text
解压后核对（PowerShell）：
  Get-FileHash '<包根>\blender_addon\endfield_camera_bridge\__init__.py' -Algorithm SHA256
  Get-FileHash '<包根>\game_mod\EndfieldCamLink.dll' -Algorithm SHA256
与包内 VERSION.txt 的「产物与校验值」比对。
注意：本工程构建不是逐字节可复现的，哈希只用于确认"包没坏"，不用于比对重建结果。
```
