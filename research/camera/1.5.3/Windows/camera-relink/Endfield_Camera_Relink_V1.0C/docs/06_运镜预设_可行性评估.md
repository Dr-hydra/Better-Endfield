# 运镜预设（扩展模块）· 可行性与执行难度评估

> 本文只做评估与设计，不含实现。评估依据是当前代码库的实际情况（不是设想）。

## 一、结论

| 维度 | 结论 |
|---|---|
| **可行性** | **高**。纯 Blender 侧功能：产物是相机关键帧，**不需要改模块 DLL、不需要碰游戏、不需要重启游戏**，与现有链路（武装 / 定镜头 / 随角色 / 120fps）完全解耦 |
| **难度** | **低到中**。真正的难点不是"执行脚本"（Blender 里执行任意 Python 是一行 `exec`），而是**给预设定一份稳定的契约与 API**，以及把 `showcase_120fps_10s.py` 里已验证的运动原语抽出来复用 |
| **工作量** | MVP（能用的最小版本）**约 4–6 小时**；完整版（参数化预设 + 运动原语库 + 3–5 个预设 + 自检）**约 1.5–2 天** |
| **主要风险** | 三条：① 预设 = 任意代码（信任边界）；② Blender 5.x action/slot API 差异；③ 预设会覆盖用户现有相机动画（必须设计成"隔离到独立 action + 可撤销"） |

## 二、现状（评估的依据）

| 事实 | 出处 |
|---|---|
| 今天的用法是**手工**：Scripting 工作区 → Open → Run Script（Alt+P），然后空格播放 | `tools\anim\README_运镜.md` §一 |
| 运镜脚本已经是一份"成品"：10 秒 / 1200 帧、6 段分镜、自适应关键帧（弧长 0.12m / 容限 0.004m）、缓动、焦点跟踪 | `tools\anim\showcase_120fps_10s.py` |
| 它**新建独立 action**（`EF_Showcase_10s`）并切过去，不动用户原有动画 | 同上 §一注 |
| 插件已有：operator、props、常驻轮询计时器（0.25s）、面板状态行、临时文件令牌通道 | `blender_addon\endfield_camera_bridge\__init__.py` |
| 插件**没有**任何"执行脚本 / 扫描文件夹"的能力 | 全文件无 `exec` / 无文件夹属性 |
| 空间约定已固定：角色头部中心 `(0,0,0)`、up `+Z`、面向 `-X`、右手边 `+Y` | README §三（与模块映射一致） |

**关键判断：这套功能全部落在 Blender 侧。** 预设产出的是关键帧 → 关键帧由插件按 120 频率推给模块 → 模块照旧绝对写游戏相机。所以它对已经调通的链路**零侵入**，出问题也只影响 Blender 里的关键帧（Ctrl+Z 可退）。

## 三、设计草案

### 3.1 预设文件夹与文件形态

- 默认目录：`<包根>\presets\`；面板里可改（`ef_bridge_preset_dir`）+ 一个「打开文件夹」按钮。
- 每个预设 = **一个 `.py` 文件**（与现有运镜脚本同形，学习成本为零）。
- 文件头写一段**元数据块**（不需要执行就能读，面板据此显示名字/说明/参数）：

```python
# EFPRESET: {"name": "环绕特写", "desc": "围绕角色 180° 环绕 + 轻微仰角",
#            "seconds": 8.0, "params": [{"key":"radius","label":"半径(m)","default":1.6},
#                                        {"key":"direction","label":"方向","default":1}]}
```

- 面板把这行当数据读（`json.loads`），**不执行**——所以列出预设是安全的。

### 3.2 预设契约（两个函数，二选一）

```python
def build(ef, params):        # 推荐：拿到注入的 API + 面板参数
    ...
```

或最简：脚本体内直接调用 `ef.*`（`ef` 由宿主注入 `exec` 的全局命名空间）。

宿主保证：注入 `ef`；其它名字（`bpy` 等）由预设自己 import。

### 3.3 预设 API（`ef`）——这是本模块的核心工作

从 `showcase_120fps_10s.py` **直接搬**已经验证过的部分：

| API | 来源 | 说明 |
|---|---|---|
| `ef.seconds(t)` / `ef.frames(t)` | `TARGET_SECONDS` / 帧率换算 | **时长用秒表达**，帧数按场景帧率推——换帧率不会让运镜变快变慢 |
| `ef.pose(theta, radius, height, aim_height, dutch)` | `camera_pose()` | 球坐标机位，环绕/推拉/升降全部由它派生 |
| `ef.ease(kind)` / `EASES` | 已有 8 种曲线 | 速度曲线 |
| `ef.key_at(t, **pose)` + 自适应加密 | `KEY_STEP_ARC/TOL` 逻辑 | 自动按弧长/加速度补关键帧（这是"手改得动"与"曲线不塌"的平衡点，已经调过） |
| `ef.focus_track(on)` | `TRACK_FOCUS` | 焦点自动跟到"相机→目标"距离 |
| `ef.new_action(name)` | `ACTION_NAME` 隔离 | **预设一律写进自己的 action**，不碰用户动画 |
| `ef.unwrap_euler(...)` | `unwrap_euler()` | 避欧拉翻转（实拍会遇到的坑） |
| `action_fcurves()` | 同函数 | **Blender 5.x slot action 兼容层**（4.x/5.x API 不同，已踩过） |

再补少量原语让预设缩短到 10–30 行：`ef.orbit(...)`、`ef.dolly(...)`、`ef.pan_tilt(...)`、`ef.crane(...)`、`ef.mark(name, t)`。

### 3.4 面板交互

```
运镜预设
  文件夹: D:\EndfieldCameraLink\presets      [打开] [刷新]
  预设:   [环绕特写 ▾]
  参数:   半径(m) [1.6]   方向 [1]
          [生成]     ← 生成后自动把帧范围设成预设时长并切到该 action
  状态:   已生成 EF_Preset_环绕特写 (960 帧 / 8.0s @120fps)
```

### 3.5 执行、隔离与撤销

1. 生成前 `bpy.ops.ed.undo_push(message="运镜预设: xxx")` → **Ctrl+Z 可整体撤销**；
2. 预设写进**独立 action**（`EF_Preset_<名字>`），不切换/不删除用户现有 action（只切当前 action）；
3. `exec` 用 `try/except` 包住：面板状态行显示一行摘要，**完整 traceback 追加到日志文件**；
4. 生成后打印/显示帧数与峰值速度（沿用 `SPEED_WARN` 的思路），便于判断"是不是太快了"；
5. 「停止」按钮：靠一次执行前后的 `bpy.app.timers` 检查点实现**可中断**（可选，见风险 5）。

### 3.6 两个实现细节坑（先说清，免得到时候返工）

- **动态下拉项的缓存问题**：Blender 的 `EnumProperty(items=...)` 用回调生成动态列表时，列表会被**缓存**，加了新预设不会自动出现在下拉里。稳妥做法是**用一个 IntProperty 索引 + 面板里自己画列表/用 UIList**（或者调一次 `bpy.context.scene.ef_bridge_refresh` 强制刷新）。这是"点一下刷新"按钮存在的真正原因，不是装饰。
- **`exec` 的命名空间要每次新建**：不要复用同一个 dict 全局，否则预设之间会串变量（第二个预设会看到第一个留下的名字），排查起来很费时间。每次执行 `exec(compile(src, path, 'exec'), {'ef': api, '__name__': 'ef_preset', '__file__': path})`。

## 四、工作分解与工作量

| 工作项 | 内容 | 估时 | 风险 |
|---|---|---|---|
| 1. 文件夹扫描 + 面板列表 | 读目录、解析 `EFPRESET` 头、缓存（目录 mtime 变了才重扫） | 1–1.5h | 低 |
| 2. 执行器 | `exec` 注入 `ef`、异常捕获、undo_push、状态行、日志 | 1–1.5h | 低 |
| 3. 预设 API 抽取 | 把 showcase 里的原语整理成 `ef`（含 5.x 兼容层、欧拉 unwrap、自适应加密） | 3–5h | 中（要把"已验证"如实搬过来，而不是重写） |
| 4. 参数化 | 参数 schema → 面板控件（数值/开关/枚举）→ 传参 | 1.5–2h | 低 |
| 5. 示例预设 | 环绕（180°/360°）、推拉、升降/摇臂、角色登场（把 showcase 改写成预设） | 2–4h | 低 |
| 6. 文档 + 自检 | 预设编写指南（契约/API/坐标约定）+ 后台 Blender 自检（跑 1 个假预设验证 API 与隔离） | 1.5–2h | 低 |
| **合计** | | **10–16h ≈ 1.5–2 天** | |

**MVP（4–6h）**：项 1 + 2 + 3（只做 `seconds/pose/key_at/ease/new_action/focus_track`）+ 1 个预设 + 状态行。做完就能"点一下生成环绕镜头"，且不动用户动画。

## 五、风险与对策

| # | 风险 | 说明 | 对策 |
|---|---|---|---|
| 1 | **预设 = 任意代码** | 点一下就在 Blender 主进程里跑，能改/删任何数据 | ① 明确"预设目录 = 可信目录"（与 Blender 插件同级信任）；② 生成前强制 `undo_push`；③ 预设只写自己 action 的约定 + 文档写明；④ 面板上显示预设来源路径 |
| 2 | **Blender 5.x action/slot API 差异** | 5.x 里 `action.fcurves` 不存在（本项目已踩） | 兼容层只写一次、放在 `ef` 里（`action_fcurves()` 已有实现），预设层不接触 API 细节 |
| 3 | **覆盖用户动画** | 预设写关键帧，若写进用户当前 action 就是灾难 | **强制隔离**：预设一律新建 `EF_Preset_<名字>` action；`new_action` 由宿主提供，预设想绕开需显式调用 `bpy` |
| 4 | **时长/帧率耦合** | 预设若按"帧号"写死，换帧率就变快变慢 | 契约规定**一律用秒**；`ef.seconds/frames` 做换算，并在生成后校验（帧数 = 秒 × 帧率） |
| 5 | **长预设卡住 UI** | Blender 主线程执行，重预设（数万键）会假死 | MVP 先限制（生成前提示预计关键帧数）；后续用分帧执行（生成器 + `bpy.app.timers`）或后台线程（Blender 数据写入必须主线程 → 只能分帧） |
| 6 | **坐标语义只在游戏侧成立** | `(0,0,0)=角色头部` 是**游戏映射的约定**，Blender 场景里要靠"参考物件/相机相对它"来表达 | 预设统一按"相对参考物件（默认 Cube）"编写；`ef.anchor()` 返回该点，文档写清 |
| 7 | 预设与环境不匹配（帧率/时长） | 用户场景可能是 24fps/没方块 | 生成前做**前置检查**：有相机、有参考物件、帧率已知；不满足就明确报错而不是生成半成品 |

## 六、明确**不做**（避免过度设计）

- 不做预设缩略图 / 预览渲染（要渲染一帧就得上 EEVEE/Cycles，代价与收益不成比例）；
- 不做预设市场 / 在线分发（本地文件夹足够）；
- 不做可视化曲线编辑（Blender 自己的曲线编辑器就是最好的编辑器）；
- 不改模块与游戏侧任何代码。

## 七、需要你定的三件事

1. **预设放哪**：包内 `presets\`（随包分发、升级会覆盖）还是用户目录（如 `%APPDATA%\EndfieldCameraLink\presets\`，升级不丢）？
   —— 建议：**默认用户目录，包内 `presets\` 作为"示例预设"源**，首次运行把它复制过去。
2. **预设文件就是 Python 吗**：是（最灵活、学习成本最低、可复用现有脚本），还是要更安全的声明式格式（JSON 描述分镜，宿主解释执行）？
   —— 建议：**先 Python**（能立刻把 `showcase_120fps_10s.py` 变成第一个预设），声明式留作以后。
3. **生成策略**：直接生成并覆盖同名 action，还是每次都新建 `EF_Preset_<名字>_<序号>`？
   —— 建议：**同名 action 存在时询问**（覆盖/新建一份），默认新建序号版，永不静默覆盖。

## 八、复用清单（直接搬，不重写）

`showcase_120fps_10s.py` 里这些已经过实拍验证，建议**逐字搬运**进 `ef` API：

- `camera_pose(theta_deg, radius, height, aim_height, dutch_deg)`
- `unwrap_euler(cur, prev)`
- `action_fcurves(action)`（Blender 5.x slot action 兼容层）
- `lerp` / `evaluate`（分段 + 时间缩放）
- `EASES`（缓动曲线表）
- 自适应关键帧加密（`KEY_STEP_MAX/ARC/TOL` 三档策略）
- `TRACK_FOCUS`（焦点跟踪到"相机→目标"距离）
- 分镜表结构（`SEGMENTS`：时间段 / 手法 / 机位 / 速度曲线）

把它们原样保留，就能保证"预设生成的镜头质量 = 已经验收过的那段展示运镜的质量"，这也是本模块**最省力、最不容易翻车**的路径。
