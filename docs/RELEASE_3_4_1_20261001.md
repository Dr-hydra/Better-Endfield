# Better Endfield 3.4.1（2026-10-01）

Windows 与 Android 版本均升级至 3.4.1，Android versionCode 为 30401。两个模型实验开关默认关闭、相互独立，开启后重启游戏生效。

## 模型实验功能

- **模型热切换**：游戏启动前开启，之后更换已安装模型包、外观和组件选项，随切换配队、重新打开角色详情等正常资源重载操作更新。双端跟踪选包变化，区分包与选项的缓存身份；已改写的缓存对象从保存的原始资源重建，停用恢复原模型，构建失败保留之前的模型。不会主动刷新游戏资源。为了重建缓存对象，开启时保留原始模型资源，会增加内存占用。
- **模型加载优化**：减少解压缓存与输出的重复副本，并在一次角色构建事务内复用等价贴图。没有降低画质或修改纹理格式，也不启用全局资源卸载。两个开关均关闭时保持原有加载行为。

本地校园包与逆兔修正版的默认选择，开关前后网格、贴图和元数据逐字节一致；解析缓存自身峰值分别从 155.72→64 MiB、101.17→16 MiB。以上是解码器统计，不是游戏内 GPU 或进程总内存峰值。

## 创作者工具

工具版本升级到 1.4.0，支持 `.bemproj.json` 导出工程：新建、打开、保存参数和重复导出。工程保存输入、配方、输出、报告以及稳定的包 ID、名称、作者和版本；相对路径以工程目录为基准，另存时保留路径指向。

角色 catalog 新增噗切娜，共 33 角色。详情与场景均已直接采样并与当前离线资源核对；资料随工具 ZIP 和 Windows 安装包分发。多子网格毛发及重复索引眼部的自动转换边界保留，详见 `CUSTOM_MODEL_PURRCHE_20261001.md`。

CLI 新增 `new-project` 与 `build`，桌面转换窗口共用同一后端。既有 `project.json + payloads` 工程仍可打包；新的导出任务工程与 BEM manifest 工程分开。

修复固定外观转换透传骨骼别名却仍生成 BEM 1.0 的问题。需要资源骨骼别名或 float32/UInt32 蒙皮时，生成完整的 BEM 1.2 组合规则及能力声明；普通内容继续兼容 BEM 1.0。组合工程补齐实际使用的纹理槽等能力声明。工具链随附更新的创作者指南、导出工程示例与 BEM 1.2 规范。

```text
BetterEndfield.BemConverter.exe new-project editable/project.json --mode pack -o character.bemproj.json
BetterEndfield.BemConverter.exe build character.bemproj.json
```

## 同时包含的修复

- Android PC 风格布局：显式启用时定期核对真实输入状态，纠正配置未变化时的状态漂移；关闭时恢复模块实际覆盖前的输入模式。新增有限状态日志，区分启动配置、字段读取和游戏拒绝。
- Android 外部“打开方式”导入：后台等待框架服务连接，区分连接与文件发布错误。
- BEM 校验：同一原始 Texture 对象可被多个材质属性共享；支持的能力可以声明但未使用，实际使用仍需声明。
- 双端提供默认关闭的“开发者：关闭模型校验”，导入与运行时采用一致模式；文件解码与必要边界仍需满足。

Windows 安装包、Android ARM64 APK 与独立 BEM Tools ZIP 已完成发布构建；噗切娜资料已包含在 Windows 安装包与工具 ZIP 中。新增资料相关 31 项回归及冻结工具导出、生产原生 BEM 校验通过。实验功能的游戏内效果、长期内存与 Android 外部导入仍需实际使用确认；没有将隔离测试当作游戏内验收。
