# 双端资源解耦与预览资源包方案

状态：分阶段实施中；读取接口与基础资源迁移见 [已实施范围](RESOURCE_PACKS.md)。全角色生成、自动下载和 Release 分发尚未完成。
日期：2026-10-28。工作位置：主工作区 `G:\Better Endfield`。

## 1. 目标与工作优先级

当前主要工作是：资源解耦、完善预览接口、自动化生成多角色预览包。完成这些基础后，再接自动更新和 Release；不能用下载流程完成代替资源能力完成。

- Windows、Android 随游戏更新的数据从程序集、APK、模块旁散落文件中解耦，统一从独立资源目录读取。
- 基础资源和预览扩展均按 Windows / Android 分包。Windows 预览以 BC7 为主要纹理表示，Android 预览以 ASTC 为主要纹理表示，客户端只下载本平台附件。
- 预览扩展可选。未安装、未覆盖当前角色或匹配失败时，仍可预览 BEM 自带模型与纹理。
- 四位资源版本；支持自动下载解压、手动导入、版本校验和回退。
- 同一仓库、一个专用资源 Release，容纳各类包及历史附件，不占软件 Latest。
- 默认不计算产物哈希。开发机上的提取 / 编码工具不成为最终用户依赖。

## 2. 当前真实基础与验证边界

依据：[原生头部预览记录](../custom_model/NATIVE_HEAD_PREVIEW_PROTOTYPE.md)、现有生成脚本和预览实现。

1. 目前真实游戏资源和实机补全验证仅覆盖梨诺 `chr_0035_liino`，其 Android 预览补全已经打通。手机“梨诺-恶魔公主”已验证补眉毛和虹膜，替换脸、头发不重复叠加。后续工作是资源外置和多角色扩展，不是重新实现梨诺安卓通路；也不能据此认定全角色可用。
2. `tools/CustomModel/build_native_head_preview.py` 是接收单角色 graph / payloads、生成多个纹理规格的样包工具，不是从游戏目录到全角色发布包的流水线。
3. 选择器假设 `<character>_uimodel` / `<character>_postmodel`、路径包含 `/Mesh_all/lod0/`，并用 face / hair / iris 等名字筛选。其他角色、变体、路径结构需要验证，不能直接套用。
4. 两端分别内嵌梨诺 BC7 / ASTC 样包，宿主解压到会话临时目录，通过 `BemPreviewGpu.native_assets` 交给共用 native 导出器。
5. `NativePreviewHead` 只认单角色原型 `pack.json`，没有仓库级索引、版本解析和多角色定位。已有精确 prefab / renderer / 材质匹配、keep / replace / hide 补全规则和粗粒度 `scene.nativeCompletion`。
6. native 有部分降级，但 Android 宿主提取 ZIP 失败仍可能在进入 native 前中止预览；要连宿主一起修。原型单文件 32 MiB、累计读取 64 MiB 的限制也不能直接变成全角色库总上限。
7. 梨诺现有规格 2K ZIP：PC 约 4.850 MiB，Android 约 2.561 MiB。分包沿用已验证的 BC7 / ASTC 方向，但不能按单角色直接估算全角色总量。

版本来源：Windows 默认配置记录游戏 `1.6.3`；Android 2026-10-15 来源快照记录 `1.6.4`。这是历史输入记录，不代表今天的安装版本。正式生成时从所选游戏 / 快照确认；未知版本允许生成开发报告，不自动产出正式版本包。

## 4. 目录、版本与兼容规则

### 4.1 持久目录

Windows 使用安装目录的 `resources/`；Android 使用应用管理的持久目录，通过系统文件选择器导入 ZIP，不要求所有文件访问权限。逻辑布局相同，绝对路径由宿主解析：

```text
resources/
  state.json                       # 本机启用 / 回退状态，不来自下载包
  core/windows/<version>/          # Android 只安装 core/android/<version>/
    manifest.json
    ...
  preview/<platform>/<version>/    # windows 或 android，只安装本平台包
    manifest.json
    characters.json
    characters/<character-id>/<variant-id>/
      pack.json
      ...
  staging/
```

资源版本目录完成后只读；会话固定持有资源快照，切换启用版本只影响新任务。旧目录无读取者后再回收，保留上一成功版。缓存另设目录。首次安装可附带基础资源目录，但不再把数据编译内嵌。

手动操作保留导入 ZIP；Windows 可提供打开目录 / 重新扫描支持解压覆盖。只读取清单列出的文件，新版删除的条目不因旧文件残留而继续生效。

### 4.2 四位版本

- 基础包：前三位跟随对应平台的游戏版本，第四位由该包独立自增，不跨平台比较。
- 预览包也分别维护平台版本：前三位按已确认的目标平台游戏版本，第四位由本平台预览包独立自增。生成来源版本与适用版本分别记录；复用另一平台数据时必须保留原来源及目标平台兼容证据，不改写来源版本。
- `schemaVersion`、软件版本、游戏版本、资源修订号分别维护。
- 先匹配包类型 / 平台 / 明确兼容记录，再按四段整数比较，不取整个 Release 数字最大的附件。
- 双端游戏版本不同不直接判定不兼容；同版本热更新也不自动保证兼容。按来源快照、精确资源身份、格式和已验证声明决定，未经验证不标已兼容。
- 允许手动回退第四位，允许主动尝试其他游戏版本的资源；无法确认身份的条目降级。未知 schema、损坏结构、非法路径不能绕过。
- 手动导入和自动更新都校验包类型、目标平台与纹理配置；Windows / Android 包不互相覆盖，也不把另一平台的附件当作可回退版本。

## 5. 统一访问层与基础资源解耦

新增职责如下，名字为拟定接口语义，不代表函数已存在：

1. `ResolveCore(platform, gameIdentity)`：返回当前基础包快照和分类入口。
2. `ResolvePreview(platform, character, prefabIdentity, gameIdentity, capabilities)`：从本平台预览包返回匹配角色条目、纹理表示、快照标识与诊断。
3. 宿主负责目录、版本和信任边界；BEM 不能指定任意本机资源根路径。native 只消费已解析的只读条目，不联网、不决定升级。
4. UI、预设、语音、战斗、动作等消费者统一改走访问层，逐项移除散落的嵌入资源名和路径。
5. Android 管理器预览可读自己的资源目录；游戏进程使用的数据继续经现有桥接 / materialize 发布到游戏可读目录，不能假定游戏可直接读管理器私有文件。
6. 跨进程副本依据资源版本 / 条目修订刷新，不能只比较大小；同长度更新也要生效。
7. 迁移期可短期外置优先、内嵌兜底。每项迁移通过后移除对应内嵌副本，避免数据双份和更新无效。

缺基础包时程序仍可启动，展示资源状态并限制依赖它的功能；不静默用不匹配数据冒充成功。缺可选预览包不影响管理、组合和保存。

## 6. 完善共用预览接口与平台资源包

### 6.1 多角色与身份

- 仓库清单 / 角色索引负责定位，条目保留 prefab asset path、world/UI 绑定、相对 renderer path、材质槽、纹理引用、来源身份。
- 形态、皮肤和模型变体独立建条目，不按相似名字混用。world/UI 可共享几何，绑定信息必须保留。
- 去重以 positions / UV / indices、submesh、骨骼、bindpose 等实际数据一致为前提，不按名称合并；生成时可直接比较规范化数据，不默认额外计算产物哈希。
- 先完成头部范围；格式预留其他组件类型，本阶段不承诺全身、武器、动画和游戏 shader 还原。

### 6.2 Windows BC7 / Android ASTC 分包

资源协议、生成代码和接口共用，实际发布两份预览 ZIP。Windows 包保留原 BC7 数据与 mip；Android 包在开发端转换为 ASTC，先沿用梨诺已验证的 ASTC 6×6 路径。无需为减少附件数改成通用 BC7 包，也不让手机承担预览资源的 BC7 转 ASTC。

几何、身份与材质导出在来源一致时复用中间产物，两份包各自携带运行所需文件，不要求用户再安装共同依赖包。仅因平台分包而不同的是编码和适配清单；来源有差异时分别提取 / 校验，不能假定两端几何天然一致。保留必要的 RGBA 纹理和已有能力检测 / 解码降级，但不以软件解码作为 Android 的默认资源分发策略。最终纹理档位由多角色清晰度、手机峰值内存和首开耗时决定。

保留颜色空间、透明度、mip、材质颜色、UV scale / offset。提取器、Python、Pillow、编码器只在开发 / 生成端运行，用户不需要安装。

### 6.3 补全规则与状态

- keep：身份匹配时补原网格；hide：绝不恢复；replace：不叠加原网格，只补精确材质 / 纹理身份匹配的缺失槽，BEM 覆盖优先。
- 投影眼影 / 发影不当普通不透明几何，未知着色能力显式报告。
- 稳定原因码至少区分：未安装、角色未覆盖、版本未确认、身份不匹配、格式不支持、损坏、部分补全、完成。返回网格 / 纹理数量、缺失项、实际资源版本。
- 区分包级 / 角色级 / 条目级错误，单角色坏数据不禁用整库；宿主解压 / 查找失败也进入降级路径。
- 无扩展包继续显示 BEM 自带内容；预览不修改安装选项或组合草稿。

### 6.4 性能与生命周期

- 按当前角色、有效 prefab / renderer 和纹理惰性读取，不把全库装入内存；打开预览不重复解压整包。
- 缓存键包含资源快照、角色 / 变体、有效选项和渲染能力；更新或回退不复用另一版数据。
- 选项切换采用任务序号与取消，只有最新任务可更新画面，旧任务及时退出。
- 已安装预览、组合预览、工具调用复用协议；分别检查 PC 常开、Android 按需打开的生命周期。
- 原型的累计 64 MiB 不作为全库上限；文件 / 结构完整性边界和内存 / 并发预算分别管理，PC 与手机预算可不同。

## 7. 自动生成预览包

### 7.1 流水线

1. **确认来源**：读取工作区配置、实际游戏版本、快照和 StreamingAssets → Persistent 覆盖关系，来源不明不正式发布。
2. **发现角色**：从角色 / prefab 索引枚举角色与变体，支持单个、列表、全量、仅变化；报告发现、排除与身份映射。
3. **提取依赖**：复用 `extract_native_bundles.py`，按 prefab 取得 mesh / material / texture / skeleton 闭包，复用同快照结果，不无条件解包全游戏。
4. **规范化**：复用 `NativeAssetReader --preview-assets`，检查缺依赖、路径、材质槽、几何与骨骼绑定；支持断点重跑。
5. **筛选组件**：把硬编码 LOD 路径和头部关键词升级为可报告的策略，结合 prefab 结构与身份；例外按角色 / 变体显式登记，无法判断的列为未覆盖，不静默遗漏。
6. **生成条目**：语义去重并保留 world/UI 绑定；来源一致时共用中间导出，再分别生成 Windows BC7 / Android ASTC payload 与 `pack.json`。缓存键区分平台和编码参数；一角色失败继续统计其他角色，但不得标为成功。
7. **汇总**：分别输出两份 ZIP、各自的 `characters.json`、包清单、覆盖报告、尺寸与耗时报告，只收录引用闭合的成功条目。报告按平台显示结果，不因 Windows 构建成功而声称 Android 编码成功。
8. **回读**：ZIP CRC、路径与文件长度、引用、网格 / 索引范围、mip 字节数、版本元数据检查；真实 native 导出回归选定条目。
9. **发布门槛**：目标角色失败或来源不明则非零退出。允许显式选子集构建，但清单必须列覆盖与缺口，不能移除失败项后宣称全量成功。

## 8. 分发与更新（后续阶段）

- `Dr-hydra/Better-Endfield` 固定资源 Tag，例如 `game-resources`；同一个 Release 保存 Windows 基础包、Android 基础包、Windows BC7 预览包、Android ASTC 预览包、`resource-index.json` 及历史版本。索引以包类型 + 平台选附件，只下载所需平台。
- 附件带完整四位版本；已发布版本不改内容，修复增加修订号。至少保留上一可用版及索引记录。
- 先上传附件并确认可用，再更新索引；索引 / 附件暂时不一致时重试并保留旧版。使用缓存和退避，不每开预览就检查下载。
- 基础资源自动更新适配版本；预览包首次自选安装，装后参与自动更新。入口包括版本 / 覆盖情况、状态、检查、导入、回退，中英文配套。
- 临时下载 → 解压 → 清单、长度、ZIP CRC、schema、引用校验 → 完成标记 → 切换启用版本。拒绝路径穿越、逃逸和异常解压；断网、取消、空间不足不破坏旧版。默认不算哈希，不把完整性校验声称为密码学来源认证。
- 手动回退后固定该包版本，暂停自动升回；可恢复自动更新。上一成功版支持离线回退。
- Android 导入走文件选择器，游戏进程副本验证升级 / 回退后一致。
- 当前 PC 软件更新器读取 `/releases/latest`，Android 按 APK 筛选发布。资源发布显式不设 Latest，软件更新器过滤资源条目，资源更新器固定查询资源 Tag。

## 9. 实施阶段与验收

| 阶段 | 交付 | 完成标准 |

P1–P3 是当前主要工作，P4 后置。P1 的梨诺回归只证明解耦通路，不代替 P3 的多角色验证。

### 验证矩阵

- 真实角色：梨诺回归；从实际发现结果再选至少三种结构特征，覆盖不同脸 / 眼睛 / 头发材质、路径和变体。发现前不编造角色覆盖。
- 功能：缺包、未覆盖、world/UI、变体、keep / hide / replace、选项切换、多来源组合、升级 / 回退缓存、部分损坏。
- 双端：Windows 消费 BC7 ZIP，Android 消费 ASTC ZIP；核对同一目标的身份 / 材质语义一致性，记录纹理能力、清晰度、首开 / 再开耗时、峰值内存和取消响应；检查已安装 / 组合预览与工具调用。另测导入错误平台包被拒绝。
- 生成：单个 / 批量 / 重跑、缺依赖、未知路径、坏数据、未知版本、去重；失败可定位且阻止发布。
- 基础资源：检查角色、语音、战斗、动作等代表消费者和游戏进程实际读取，不仅判断文件存在。
- 报告明确区分提取成功、静态回读、native 导出、PC 显示、Android 显示；自动检查不冒充实机验收。

尚待实测：双端全角色总规模、变体差异、Android ASTC 批量生成耗时及多角色显示内存、跨平台资源身份复用范围、特殊 shader 显示边界。先用流水线和报告取证，再决定默认纹理档位和首次发布角色集合。

本方案不承诺通过资源包修复 hook、生成缺失身体几何、自动修补接缝或还原完整游戏着色。
