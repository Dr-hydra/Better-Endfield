# 运镜预设 · 编写与使用

> 插件 **0.3.0** 起，侧栏（`N`）→ Endfield Camera → **运镜预设**：读取一个文件夹里的 `.py` 运镜脚本，
> 点一下就在 Blender 里执行并生成运镜关键帧。
> **0.3.1**：预设用**下拉栏**（点一下展开全部预设、直接点着切换），目录内容**自动读取**。
> **0.3.3**：三个示例预设改为**匀速**、**参数精简**、**关键帧尽量少**，并新增通用参数 **运镜时间**。

## 一、随包自带的三个预设（参数已精简）

| 预设 | 参数 | 关键帧（每条曲线） | 实测 |
|---|---|---|---|
| **环绕** | 环绕半径、环绕角度 | 62 个（180°/1.8m） | 水平面匀速绕中心方块，高度与视线落点都锁在中心；逐帧速度比 1.0004、折角 ≤2.90°、转动台阶比 1.024 |
| **推拉** | 起始半径、结束半径 | **2 个** | 匀速推近/拉远；速度比 1.0001、折角 0°、转动台阶比 1.000 |
| **升降** | 起始高度、结束高度 | 6 个（默认跨度） | 匀速垂直起落；速度比 1.0000、折角 0°、转动台阶比 1.155 |

**三个预设的"运镜时间"是通用参数**（不在预设自己的参数表里），面板上单独一项：

```
运镜时间(秒, 默认 8.0)  [ 8.00 ]      ← 改它 = 整段运镜等比缩放
```

- 预设内部一律按**归一化时间**（0 → 1）书写；帧数 = 运镜时间 × 场景帧率。
- 把 8 秒改成 4 秒 = **整段等比缩放到一半**：帧范围 961 → 481、关键帧位置按比例前移，
  速度与构图完全不变（实测 3s/6s、4s/8s 两档都精确减半）。
- 切到另一个预设时，面板会把它的默认参数与默认秒数填上；**恢复默认**按钮（↺）可随时重新填一遍。

### 关键帧数量由**四条几何判据**自动求解（不是拍脑袋定的）

匀速靠 **LINEAR 插值**保证（逐帧速度比实测 1.0000），所以关键帧只需满足精度；`ef.orbit_linear`
等函数会用**数值搜索**找出满足下列全部判据的最小关键帧数：

| 判据 | 默认 | 含义 | 不满足时的观感 |
|---|---|---|---|
| **弦偏差** | ≤ 1 cm | 折线离真实轨迹多远 | 圆弧/直线走偏 |
| **折角** | ≤ 3° | 相邻线段的方向变化（圆弧被折线近似时的"棱角"） | **每隔一段"拐一下"**——早期 16 个关键帧时每 12° 拐一次，就是被看出来的"不匀" |
| **瞄准偏差** | ≤ 0.5° | 视线偏离中心方块的角度 | 目标在画面里上下漂移 |
| **转动台阶比** | ≤ 1.25 | 相邻两段**转动角速度**之比（LINEAR 下角速度是分段常数，关键帧处会有台阶） | **转到某处"顿一下"**——升降关键帧太少时台阶比能到 2.2 倍 |

> 注意区分：转动速度的**全局** max/min（升降实测 1.59）是**几何必然** —— 相机要一直咬住中心，
> 俯仰角是 atan 曲线，中段本来就该转得快些。只有**相邻段的台阶比**才是缺陷，判据只约束它。

想更顺就收紧判据（例如 `ef.orbit_linear(..., kink_deg=1.5)`，关键帧会翻倍）；
想更省关键帧就放松（`kink_deg=6` 约 32 个）——这是**光滑度 ↔ 关键帧数**的直接取舍。

## 二、怎么用（三步）

1. 侧栏 `N` → **Endfield Camera** → 找到 **运镜预设** 框；
2. 框里就是一个**下拉栏**：点一下展开，里面是预设文件夹里的全部预设（**自动读取**）；
3. 点选中想要的预设 → 按 **生成这个运镜**。

### 预设放哪：**包内**（v0.3.6 起，便于整个包分发）

| 位置 | 说明 |
|---|---|
| `<包根>\presets\` | **默认预设目录**。预设数据与路径设置都在包内：把整个包拷给别人，预设跟着走 |
| `<包根>\paths.ini` 的 `preset_dir` | 路径设置也在这里（留空则自动取 `<包根>\presets`）；改这一行即可全局生效 |
| 插件目录内 `presets\` | 随插件分发的**示例种子**：目标目录缺文件时会自动补齐；用 ZIP 单独装插件（没有包根）时它就是默认目录 |
| 面板里的「预设文件夹」 | 想临时用别的目录时填这里；留空即用包内目录（面板会显示解析出来的实际路径） |

> 插件装在 `%APPDATA%\...\addons\` 里、与包根没有相对关系，所以**安装脚本**会把包根写进
> 插件目录下的 `package_path.txt`，插件据此定位包内 `presets\` 与 `paths.ini`。
> 因此：换包的位置后**重新跑一次安装**（控制台菜单 [1] 安装配置，或菜单 [9] 只安装 Blender 插件）即可。

下拉栏下面会显示当前预设的说明、文件名，以及它声明的参数输入框。
换了文件夹或往里加了新预设文件后，**下拉栏下次重绘就自动跟上**（点刷新图标可立即重扫）。

生成后：自动新建一个**独立 action**（`EF_Preset_<名字>`）并切过去，设置好帧范围，并把播放头回到第 1 帧。
按 **空格** 播放即可（游戏侧已武装时，画面会同步跟着走）。

| 行为 | 说明 |
|---|---|
| **不覆盖用户动画** | 预设永远新建 action；同名已存在时自动加序号（`_2`、`_3`…）。你原来的 action 只是被切走，没有被删改 |
| **可撤销** | 生成前会 `undo_push`，出问题 `Ctrl+Z` 一次整体退回 |
| **出错不崩** | 预设抛异常时面板只显示一行摘要，完整 traceback 追加到 `%TEMP%\EndfieldCameraLink_preset.log` |
| **参数** | 预设声明的参数（最多 4 个数值）会显示成输入框，值会传进 `ef.params` |
| **自动读取** | 面板每次重绘都会扫一遍预设目录（按目录/文件修改时间缓存，不会反复读盘）；下拉栏里陈旧或越界的选中项会被自动夹回合法范围 |
| **示例预设会自动同步** | 插件升级后，**随包分发的示例预设会自动更新到你目录里**（旧版先备份到 `_bundled_backup/`）。你若亲手改过某个示例，插件**不会动它**，而是把新版放到 `_bundled_new/` 供对比 |
| **打开文件夹** | 文件夹图标只是"方便你往里放脚本"，不是使用流程的必经一步 |

> ⚠️ **这一条是踩过的坑**：早期版本只在"预设目录不存在"时复制一次示例，
> 于是插件升级后你目录里一直是**旧脚本** —— 表现为"明明升级了，运镜还是老毛病
> （环绕首尾突变、推拉开头先后退、升降结尾改方向）"，而代码其实早就改对了。
> 0.3.5 起会自动同步，所以以后升级只要重启 Blender 即可，不必手动删目录。
> 想手动看/改示例：直接编辑你目录里的那份即可（改过之后插件就不会再覆盖它）。

## 二、预设文件长什么样

就是一个普通 Python 文件，**文件头一行（可跨行注释）声明元数据**：

```python
# EFPRESET: {"name": "环绕特写", "desc": "围绕角色 180° 环绕", "seconds": 8.0,
#            "params": [{"key": "radius", "label": "半径(m)", "default": 1.6}]}

def build(ef, params):
    ef.orbit(0.0, 8.0, "ease_in_out", 0.0, 180.0, radius=ef.param("radius", 1.6), height=0.25)
    ef.finish(8.0)
```

- 元数据**不执行代码**就会被解析（所以"列出预设"是安全的）；JSON 不合法时会退回用文件名当名字。
- `build(ef, params)` 是入口；不写 `build` 也可以，脚本体直接调用 `ef.*` 一样有效。
- 参数上限 4 个，都是数值型（`ef.param("key", 默认值)` 取用）。

## 三、`ef` API（预设里唯一需要关心的东西）

### 时间

| 调用 | 说明 |
|---|---|
| `ef.fps` | 当前场景帧率（数值） |
| `ef.seconds(s)` / `ef.frames(s)` | 秒 → 帧数换算 |
| `ef.frame_at(s)` | 第 1 帧为 0 秒时，`s` 秒对应的帧号 |

**规则：预设里一律用"秒"。** 帧数由宿主按场景帧率换算 —— 这样换帧率（120/60/30）时运镜**速度不变**。

### 机位（球坐标）

角色头部中心 = 坐标系原点（来自**参考物件**，即名为 `Cube` 的物体 —— v0.3.9 起固定用它；
找不到就用世界原点）。

| 参数 | 含义 |
|---|---|
| `theta` | 方位角（度）。`0` = 角色正前方（角色面向 `-X`），增大 → 转向角色右手边（`+Y`） |
| `radius` | 到角色的水平距离（米） |
| `height` | 相机高度（米，相对角色头部中心，`+Z` 向上） |
| `aim_height` | 视线落点高度（米）——控制"看头/看胸/看脚" |
| `dutch` | 荷兰角（度，绕视线滚转） |

`ef.pose(...)` 返回 `(世界位置, 旋转矩阵, 到目标距离)`；一般用下面的封装即可。

### 生成运镜

| 调用 | 说明 |
|---|---|
| `ef.key(t, theta=…, radius=…, height=…, aim_height=…, dutch=…)` | 在 `t` 秒打一个关键帧 |
| **`ef.orbit_linear(x0, x1, θ0, θ1, radius, …)`** | **匀速环绕**；关键帧数按"弦-弧容差"自动取最少 |
| **`ef.dolly_linear(x0, x1, r0, r1, …)`** | **匀速推拉**；直线路径 → 2 个关键帧 |
| **`ef.crane_linear(x0, x1, h0, h1, …)`** | **匀速升降**；直线路径 → 2 个关键帧 |
| `ef.sweep(t0, t1, 缓动, 起态, 终态)` | 缓动版（自适应贝塞尔加密）；`t0/t1` 是**秒** —— 缓动/复杂分镜才用 |
| `ef.orbit / ef.dolly / ef.crane` | 缓动版环绕/推拉/升降（同上，参数用秒） |
| `ef.mark(名字, x)` | 在归一化时间 `x` 处放时间轴标记 |
| `ef.finish(总秒数=None)` | 收尾：设关键帧插值（匀速段 LINEAR / 缓动段 BEZIER+AUTO_CLAMPED）、帧范围、汇总 |

**时间参数有两套，别混用**：

- **`*_linear` 系列与 `ef.mark` / `ef.frame(x)` 用归一化时间 `0 → 1`**（推荐）——
  这样"运镜时间"参数一改就整段等比缩放，预设里不需要任何换算；
- `sweep / orbit / dolly / crane`（缓动版）与 `ef.frame_at(秒)` 用**秒** —— 给复杂分镜用。

缓动可选：`linear` / `ease_in` / `ease_out` / `ease_in_out` / `ease_in_cubic` / `ease_out_cubic`。

`sweep` 的起态/终态是字典，例如：

```python
ef.sweep(1.0, 5.0, "ease_out",
         dict(theta=30, radius=2.6, height=0.42, aim_height=0.08, dutch=0),
         dict(theta=30, radius=0.72, height=0.04, aim_height=0.02, dutch=3))
```

### 关键帧密度（为什么不用自己补帧）

`sweep` 内部按三条策略自适应加密（经验证过的参数，与 `tools\anim\showcase_120fps_10s.py` 同一套）：

- **快速段按弧长**：相邻关键帧位移不超过 `step_arc=0.12m`（弧线误差 < 2mm）；
- **加/减速段按偏差容限**：`step_tol=0.004m`，保证"缓起缓停"的形状不被贝塞尔手柄压平；
- **慢速段放宽**到 `step_max=0.25s`（关键帧少、便于手改）；
- **首尾各 0.15 秒再加密一档**：首末关键帧没有外侧邻居，手柄会被 `AUTO_CLAMPED` 压平，不加密就把设计的起手/收尾吃掉了。

想更贴合或更省关键帧，直接传参覆盖：`ef.sweep(..., step_arc=0.06)`。

## 四、三条硬规则（都是踩过的坑）

1. **时长用秒，不用帧号**。写死帧号 → 用户换帧率后运镜变快/变慢。
2. **别自己动 `bpy` 的动画数据**（不要 `actions.new` / `animation_data.action = …`）。
   宿主已经建好独立 action 并切过去了；你只管 `ef.*`。自己动 = 绕过隔离，可能覆盖用户动画。
3. **别用 `action.fcurves`**。Blender 5.x 里这个属性不存在（4.4+ 改成槽位动作），要用
   `action_fcurves()`（宿主已提供，`ef` 内部也在用）。

## 五、自检覆盖了什么

`source\tools\verify_addon_selftest.py`（后台 Blender 跑）对预设模块断言了 12 项，其中包括：

- 扫描到预设、元数据跨行 JSON 能解析出名字与参数；
- 执行后**确实新建** `EF_Preset_*` action，且**用户原有 action 未被删除/改写**（对比执行前后 action 总数）；
- 关键帧确实写入、机位确实在动、帧范围 = 秒 × 帧率、时间轴标记已放置；
- 同名预设再执行一次 → 自动生成 `_2` 版本（**绝不覆盖**）；
- 故意抛异常的预设 → 不抛出、状态行给出一行摘要、完整 traceback 落盘。

## 六、自己加预设的推荐姿势

1. 复制 `01_orbit_180.py` 改名；
2. 改 `EFPRESET` 头里的名字/说明/时长/参数；
3. 用 `ef.key` 写分镜表、用 `ef.sweep / orbit / dolly / crane` 连接段落；
4. 回插件面板点 **刷新** → 点你的预设 → **生成这个运镜**；
5. 不满意就改文件再生成（每次都新建 action，不会互相覆盖，方便 A/B 比较）。

> 想看更复杂的分镜范例（6 段、10 秒、特写/环绕/推拉/摇移混合、速度曲线设计），
> 看 `tools\anim\showcase_120fps_10s.py` —— 它是本模块的"教科书版本"。
